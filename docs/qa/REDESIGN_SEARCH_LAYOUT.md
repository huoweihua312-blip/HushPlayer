# 搜索页布局重设计（v1.0.13）

用户反馈：搜索页在未输入时出现「空的专辑/歌手/歌曲标题 + 空表格」，在线模式则把音源胶囊、
状态、最近搜索、空状态、结果表全部堆在一起，显得杂乱。要求重新设计布局。

## 旧布局的问题

1. 本地页：`local_empty` 与结果滚动区同时存在，空查询时结果区的三个小节标题和空表格仍然占位。
2. 在线页：胶囊栏、状态、最近搜索、空状态、结果表 **五行常驻**；搜索中空状态与列表互相遮挡。
3. 最近搜索常驻一行，即使已有结果也占空间。
4. 本地结果顺序是 专辑 → 歌手 → 歌曲，最常看的歌曲反而在最下面。

## 新布局

### 本地
- `QStackedWidget` 两页：**引导页**（EmptyState，占满宽高、内容居中）与 **结果页**（滚动区）。
- 空查询 / 无结果 → 引导页；有结果 → 结果页，顺序改为 **歌曲 → 专辑 → 歌手**。
- 歌曲表格高度 = `min(420, 56 × 行数 + 44)`，避免固定大空白。

### 在线
- 工具栏：音源胶囊（横向滚动） + 「更多音源」 + 「管理音源」 + 主按钮「全部播放」。
- 状态行：`130 首结果 · 7 个音源 · 1 个失败`，搜索中实时变为
  `已找到 N 首 · 正在搜索 x/y 个音源…`。
- 内容：`QStackedWidget` 两页——空闲页（EmptyState + 最近搜索 chips）与结果表。
- 空闲时不显示工具栏与状态行；搜索中立即切到结果页并把空表提示改为「正在搜索…」。
- 「更多音源」仅在确有音源被收敛时出现。

## 证据

- `tools/probe_r13_layout.py`（真实 `HushApp`，125%）：本地空闲、在线空闲、在线结果三张截图。
- 在线结果页实测：130 条结果、7 个音源、1 个失败，胶囊显示各源计数，表格 12 行可见。
- 自动化：`tests/test_search_incremental.py` 新增 2 条布局状态用例；全量 145 passed。
