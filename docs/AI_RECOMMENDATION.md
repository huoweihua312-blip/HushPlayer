# 「播放我推荐的歌」方案（仅设计，未实现）

目标：在现有本地库 / 收藏 / 歌单 / 收听历史之上，推荐**用户还没收藏、也没在歌单里**的在线歌曲，并能一键开始一个推荐队列。

## 一、可用的信号（现有数据）

| 信号 | 表 / 文件 | 用途 |
| --- | --- | --- |
| 收藏（我喜欢） | `playlists` 系统歌单 + `playlist_items` | 正向偏好，最强 |
| 自建歌单 | 同表 + 歌单名 | 场景/风格线索 |
| 收听次数 / 最近播放 | `stats.json`（track_id → count/last_played） | 复听偏好、衰减权重 |
| 跳过行为 | `stats.json`（skipped） | 负向信号 |
| 歌曲元数据 | `tracks`（genre、year、album、artist） | 内容相似度 |
| 在线搜索 | `OnlineClient.search` | 候选来源 |

## 二、推荐流程（离线优先，联网补全）

1. **画像**（本地计算，毫秒级）
   - 歌手权重 = Σ(收藏×3 + 完播×2 + 跳过×(-2)) × 时间衰减（半衰期 30 天）；
   - 风格/年代权重取自收藏与高频歌曲的 `genre/year`（缺失时忽略）；
   - 取 Top 8 歌手 + Top 5 风格作为“种子”。
2. **候选生成**
   - 对每个种子歌手：`search("<歌手>")` 取前 20 首；
   - 对种子风格：用歌单里同风格歌曲的标题关键词或平台“相似歌单”不可用时，退化为按风格词搜索；
   - 过滤：已收藏、已在任一歌单、已在最近 30 天播放过（可配置）；
   - 打分：歌手匹配 0.45 / 风格 0.2 / 时长合理 0.05 / 热度（平台返回的 play count，若有）0.2 / 新鲜度 0.1；
   - 去重：`(source_id, remote_id)` + 标题+歌手规范化。
3. **结果**：20 首，来源标注平台；先全部解析成可播 URL 的不现实，所以只解析前 3 首，其余点播时按现有 `_resolve_online` 流程。
4. **入口**：首页新增「为你推荐」卡片 + 「播放推荐」按钮；推荐队列 = 推荐列表 + 现有队列尾部策略（替换/追加可选）。

## 三、隐私与离线

- 全部计算在本地；仅在生成候选时调用已启用的在线音源搜索。
- 无网络时：只用本地库做“同歌手/同风格未播放”推荐（可离线）。
- 提供开关：设置 → 播放 → 「个性化推荐」，关闭后不读取 stats。

## 五、风险

- 在线源搜索结果质量参差（已有 `matching.py` 可复用做标题/歌手校验）；
- 平台限流：一次推荐最多 8 次搜索，需节流与缓存（10 分钟）；
- 冷启动用户（无收藏/无历史）：退化为「本地库随机 + 热门搜索词」，并在 UI 说明“多听几首后推荐会更准”。
