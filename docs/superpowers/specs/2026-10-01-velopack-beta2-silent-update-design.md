# Velopack beta2 静默更新测试设计

## 目标

为 HushPlayer 制作一个独立的 `1.0.1-beta.2` 测试版本，用于验证真正的应用内静默更新。beta1 和现有正式更新流程继续保留，beta2 不直接替换当前正式更新入口。

验收目标是：用户确认更新后，程序自动下载更新包，提示重启，正常关闭当前进程，由 Velopack 更新器完成版本切换并重新启动，不再进入 Inno Setup 可见安装向导。

## 方案选择

采用并行测试通道，而不是立即替换正式更新链路。

- beta1 继续使用完整安装包和可见安装向导，作为回退路径。
- beta2 使用 Velopack 的按版本目录和 `Update.exe` 更新结构。
- beta2 使用独立的测试更新源和测试安装目录，避免覆盖 beta1。
- 只有 beta2 完成真实安装、下载、退出、替换、重启和失败回退测试后，才考虑切换正式更新入口。

## 代码与构建边界

1. 保留 `AppUpdateService` 作为正式更新服务，不删除或重写现有 Inno Setup 路径。
2. 仅在检测到 Velopack 安装结构和测试更新源时启用 `VelopackUpdateService`。
3. beta2 的更新清单、安装包和更新包使用独立版本号 `1.0.1-beta.2`。
4. 不迁移用户数据；用户数据继续位于 `%APPDATA%\\HushPlayer`。
5. 不修改播放、歌词、媒体库和设置数据结构。

## 更新流程

```text
Velopack beta2
  -> 检查测试更新源
  -> 用户确认下载
  -> 后台下载并显示进度
  -> 用户确认重启
  -> Update.exe 等待播放器退出
  -> 切换版本目录
  -> 自动启动新版本
```

更新失败时，保留旧版本目录并重新启动旧版本。禁止使用 `os._exit()`、强制 kill 或无条件终止线程掩盖退出问题。

## 测试范围

- beta2 首次安装到独立目录。
- beta2 检查 beta2 更高版本的测试更新。
- 播放本地歌曲时更新。
- 播放在线歌曲或缓存任务进行时更新。
- 桌面歌词开启时更新。
- 更新前取消下载。
- 更新下载失败或网络中断。
- 更新器等待主进程退出并自动重启。
- 更新失败后旧版本可启动。
- 用户数据、音乐库、歌单、收藏和设置保留。
- 连续执行两次启动、退出和更新。

## 风险与回滚

风险主要集中在 Velopack 的原生更新器、安装目录结构、Windows 文件锁和更新源配置。beta2 不覆盖 beta1，出现问题时关闭 beta2 测试目录即可；正式版仍使用 beta1 的可见安装更新流程。

回滚方式是停止发布 beta2 更新源，继续使用 beta1 更新清单，不修改用户数据目录，也不删除 beta1 安装。

## 完成标准

只有在真实安装包上确认更新后不再出现 Inno Setup 窗口、能自动重启、用户数据完整保留且失败可回退时，才允许把 Velopack 设为正式更新入口。
