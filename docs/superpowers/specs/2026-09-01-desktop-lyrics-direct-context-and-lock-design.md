# HushPlayer 桌面歌词直接右键与单按钮锁定设计

## 1. 变更背景

现有桌面歌词在进入交互状态后，会在右上角显示“归位 / 穿透 / 关闭”三按钮工具栏。实机验收认为这组控件遮挡感较强，也让“调整歌词设置”多绕了一步。

本规格是对 `2026-09-01-desktop-lyrics-quick-settings-design.md` 的增量修订。原有快捷设置内容、即时预览、自动保存、开放字体限制和播放器底栏入口继续有效；本轮只调整桌面歌词窗口自身的交互入口。

## 2. 已确认方案

采用“直接右键 + 单一锁按钮”方案：

- 完全移除右上角“归位 / 穿透 / 关闭”工具栏，不保留文字按钮或工具栏背景。
- 桌面歌词解锁时，右键歌词文字区域直接打开现有快捷设置浮层。
- 桌面歌词解锁时，左键拖动继续调整位置。
- 桌面歌词悬停时只浮现一个锁图标；解锁态点击可锁定，锁定态点击可解锁。
- 锁定态平时保持 Windows 鼠标穿透；鼠标停留到歌词区域时，临时显示解锁按钮并接收该按钮的点击。
- 播放器底栏“桌面歌词”按钮继续负责左键显示/隐藏，并保留右键打开设置的备用入口。
- “恢复默认位置”保留在快捷设置浮层中；关闭桌面歌词继续使用播放器底栏按钮。

## 3. 状态模型

桌面歌词窗口不得再用一个布尔值同时表达“用户锁定偏好”和“当前 Windows 输入标志”。拆分为两个内部状态：

1. **锁定偏好**：由现有 `floating_lyrics_passthrough` 字段表示，并通过现有设置桥保存。
2. **实际输入穿透状态**：反映当前是否设置 `WindowTransparentForInput`。锁定态显示解锁按钮时可临时关闭该标志，但不得改写锁定偏好。

状态行为如下：

| 状态 | 歌词窗口输入 | 悬停按钮 | 左键拖动 | 右键设置 |
| --- | --- | --- | --- | --- |
| 解锁、未悬停 | 可交互 | 隐藏 | 可用 | 可用 |
| 解锁、悬停 | 可交互 | 显示“锁定” | 可用 | 可用 |
| 锁定、未悬停 | 鼠标穿透 | 隐藏 | 不可用 | 不可用 |
| 锁定、悬停 | 临时可交互 | 显示“解锁” | 不启动拖动 | 解锁前不打开设置 |

Qt 的 `WindowTransparentForInput` 作用于整个顶层窗口，不能只让一个子按钮例外。因此锁定态浮现解锁按钮期间，桌面歌词窗口会短暂接收输入；鼠标离开后自动隐藏按钮并恢复完整穿透。这是满足“平时穿透”和“悬停可解锁”的必要边界，不引入全局鼠标钩子。

## 4. 交互细节

### 4.1 直接右键

- 解锁态下，在桌面歌词透明窗口范围内右键，发出带全局坐标的设置请求。
- 主窗口复用同一个 `DesktopLyricsQuickSettingsPopover`，在右键点附近显示并夹紧到当前屏幕可用区域。
- 右键不得触发拖动、切换桌面歌词显示状态、切换页面或改变播放状态。
- 浮层已显示时再次右键歌词，可按现有切换语义关闭浮层。
- 锁定态不监听穿透到下层应用的右键；用户先点击浮现的解锁按钮，再直接右键歌词。

### 4.2 单一锁按钮

- 使用项目现有图标体系中的轮廓锁定 / 解锁图标，不使用文字或 Emoji。
- 按钮约 `32 × 32 px`，放在歌词窗口上边缘中央，不使用原右上角位置。
- 默认完全隐藏；只在鼠标进入歌词窗口后浮现。
- 按钮本身无常驻背景，仅在悬停、按下或键盘聚焦时显示克制的圆角底色和焦点描边。
- 提供“锁定桌面歌词”或“解锁桌面歌词”的工具提示与可访问名称。
- 点击后通过主窗口现有设置更新链路即时应用并自动保存，不直接写 `settings.json`。

### 4.3 悬停与退出

- 解锁态使用窗口事件显示锁按钮；锁定态沿用轻量光标轮询，因为穿透窗口收不到普通进入事件。
- 锁定态检测范围改为完整歌词窗口，不要求先命中边缘热区。
- 鼠标离开后沿用短暂退出延时，避免锁按钮在边缘移动时闪烁。
- 快捷设置浮层打开、拖动正在进行或指针位于锁按钮上时，不启动退出计时。
- 任何临时交互状态都不得把用户的锁定偏好静默改为另一个值。

## 5. 组件调整

### 5.1 `DesktopLyricsWindow`

- 删除三按钮工具栏及其布局、样式、几何计算和按钮槽函数。
- 新增单一锁按钮以及锁定偏好、实际输入穿透状态的独立管理。
- 新增桌面歌词设置请求信号，携带右键的全局位置。
- 新增锁定偏好变更请求信号，由主窗口负责校验、预览和保存。
- 保留无背景、两行歌词、位置夹紧、重复渲染抑制、拖动和歌词同步行为。

### 5.2 `DesktopLyricsQuickSettingsPopover`

- 保留现有按钮锚定显示方法。
- 增加按全局坐标显示的方法，复用同一套屏幕边界夹紧逻辑。
- 不读取播放状态，不直接持久化设置。

### 5.3 `MainWindow`

- 将桌面歌词设置请求连接到现有快捷设置浮层。
- 将锁定偏好变更连接到现有 `_on_desktop_lyrics_setting_changed()` 链路。
- 播放器底栏右键入口保持不变，作为锁定态或歌词不可见时的备用入口。

## 6. 数据流

```text
解锁态右键桌面歌词
        ↓ 全局坐标
MainWindow 同步当前 SettingsSnapshot
        ↓
DesktopLyricsQuickSettingsPopover 在右键点附近显示

点击锁定 / 解锁按钮
        ↓ floating_lyrics_passthrough
MainWindow 生成候选 SettingsSnapshot
        ├─→ DesktopLyricsWindow.apply_settings() 即时应用
        └─→ 250 ms 防抖 → LegacySettingsBridge.save_snapshot()
```

保存失败时继续沿用现有回退：恢复最近一次成功保存的快照、重新应用窗口状态并在快捷设置浮层显示行内错误。锁按钮不得弹出模态错误框，也不得影响播放。

## 7. 数据和高风险边界

- 不新增第三方依赖。
- 不新增或迁移设置字段，继续使用 `floating_lyrics_passthrough`。
- 不修改 `library.json`、`playlists.json`、`stats.json` 或设置文件结构。
- 不修改歌词解析、活动行、同步时间轴、沉浸歌词、播放队列和 `QMediaPlayer` 状态管理。
- 只对桌面歌词窗口输入状态进行小范围调整；若发生回归，可单独回滚实现提交，不需要转换用户数据。

## 8. 验收与检查

自动检查至少覆盖：

- 桌面歌词窗口不再创建原三按钮工具栏。
- 解锁态右键发出一次设置请求，且不启动拖动。
- 主窗口收到请求后，在全局点击点附近显示既有快捷设置浮层。
- 解锁态悬停只显示一个锁按钮，点击后请求保存 `floating_lyrics_passthrough=True`。
- 锁定态未悬停时包含 `WindowTransparentForInput`；悬停显示解锁按钮时只临时关闭输入穿透，不改变锁定偏好。
- 锁定态离开后恢复输入穿透，按钮隐藏且不闪烁。
- 解锁后左键拖动、位置保存和边界夹紧继续正常。
- 播放器底栏左键显示/隐藏和右键备用设置入口保持正常。
- 快捷设置的颜色、字体、字号、透明度、宽度、穿透和归位功能继续通过原链路保存。
- 执行修改 Python 文件的 `py_compile`、UTF-8 解码、桌面歌词回归测试及 Git 差异检查。

手动验收步骤：

1. 显示桌面歌词，确认右上角不再出现三按钮工具栏。
2. 解锁状态右键歌词，确认设置浮层在指针附近打开。
3. 解锁状态拖动歌词，确认位置保存。
4. 悬停歌词，确认只出现一个位于上边缘中央的锁图标。
5. 点击锁定，确认鼠标离开后可以点击穿透到歌词下方窗口。
6. 再次停留到歌词上，确认解锁按钮浮现；点击后恢复拖动和右键设置。
7. 重启程序，确认锁定状态与其他桌面歌词设置保持。
8. 播放、暂停、切歌并打开沉浸歌词，确认播放和歌词同步未受影响。
