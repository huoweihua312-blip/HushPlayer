# HushPlayer 产品级视觉系统重整设计

## 目标

让 HushPlayer 从“功能已经可用的播放器”变成一款用户愿意长期打开、长期使用的 Windows 音乐库工具。重点不是增加装饰，而是建立稳定、克制、可识别的视觉系统，让用户在音乐库、收藏、歌单、在线搜索、来源管理、设置和播放过程中始终感受到同一个产品。

本轮名称：**Quiet Orbit Graphite（石墨听音室）**。

## 用户问题

当前版本存在以下可感知问题：

- 深色主题的暗绿表面过多，背景层级显脏且长时间观看容易疲劳。
- 主应用、播放器、沉浸歌词、封面氛围和设置弹窗存在各自的硬编码颜色。
- 当前字体回退顺序优先使用微软雅黑；本机已有的 Noto Sans SC 与 MiSans 没有成为主要中文字体。
- 页面标题、列表、按钮和弹窗使用多套字号与字重，视觉节奏不稳定。
- 导航、页头、列表和弹窗的选中、悬停、焦点、播放中和失效状态不完全一致。
- 高频页面仍有“标题 + 裸列表 + 小按钮”的组合，内容区域缺少稳定的工作面板边界。
- 在线搜索、失效歌曲恢复、来源管理和设置操作缺少统一的状态反馈语言。

## 设计原则

1. **长期舒适优先**：中性石墨灰、低饱和强调色、稳定的文字对比和克制的动效。
2. **一个产品，一套令牌**：所有普通页面、弹窗、播放器和设置控件优先使用主题令牌，不在组件中散落颜色。
3. **内容优先**：封面、歌名、歌手、专辑和播放状态是主信息；边框和装饰只用于建立层级。
4. **状态不依赖颜色单独表达**：播放中、不可用、错误、成功和禁用状态同时使用图标、文字、字重或结构差异。
5. **鼠标和键盘都自然**：鼠标点击不留下装饰性焦点边框；Tab、快捷键和无障碍焦点仍然可见。
6. **不改变用户数据和播放习惯**：只改 UI 表现与反馈，不改播放核心、队列、数据结构、来源协议和更新流程。

## 视觉系统

### 色彩

深色主题改为中性石墨灰：

- `Ink`：应用和标题栏背景，接近黑色但不使用纯黑。
- `Rail`：侧栏背景，比 Ink 略亮，保持稳定的导航边界。
- `Canvas`：内容画布，比 Rail 略亮，减少大面积暗绿。
- `Panel`：工作面板、歌曲列表和搜索结果表面。
- `Raised`：弹窗、菜单和设置面板表面。
- `Fog`：主文本与次级文本的灰阶层级。
- `Signal Gold`：播放、收藏、确认和少量当前状态强调；不用于大面积背景。
- `Status`：错误、警告、成功和不可用状态使用语义色，并配合文字或图标。

浅色主题保留现有兼容性，但使用同一套语义命名和层级逻辑。沉浸歌词可以保留独立的氛围背景，但控制层、按钮、文字和状态仍从主题令牌取色。

### 字体

使用本机已有字体，不增加第三方依赖或下载流程：

1. `Noto Sans SC`
2. `MiSans`
3. `Microsoft YaHei UI`
4. `Segoe UI Variable Text`
5. `Segoe UI`

字体令牌统一为：

- Caption：12px
- Metadata：13px
- Body：14px
- Control：14px
- Track title：15px
- Section title：20px
- Page title：30px
- Hero title：34px

字号只允许通过 `ThemeFonts` 或共享组件使用。特殊歌词画布保留独立字号设置，但普通页面不得再直接硬编码字号。

### 间距、圆角和边界

- 间距节奏：4 / 8 / 12 / 16 / 24 / 32px。
- 控件高度：32px（紧凑工具按钮）、40px（普通按钮）、44px（主要操作）。
- 圆角：8px（小控件）、10px（普通控件）、14px（面板）、16px（主表面）。
- 边框使用低对比度分隔色；不能用金色边框表达普通选中态。
- 选中态优先使用表面层级、文字字重和图标状态；焦点态只服务键盘导航。

## 组件和页面结构

### 第一批：视觉基础层

涉及：`theme/tokens.py`、`theme/styles.py`、字体解析、通用按钮/输入框/列表/滚动条、播放器进度控件和导航焦点行为。

产出：

- 石墨灰暗色主题。
- 可验证的中文字体回退链。
- 统一控件状态：默认、悬停、按下、键盘焦点、禁用。
- 统一普通按钮、主要按钮、图标按钮、输入框和弹窗基础样式。
- 消除关键运行路径中的硬编码主题颜色。

### 第二批：高频页面

涉及：标题栏、侧栏、`PageHeader`、`SectionToolbar`、音乐库、我喜欢、歌单、浏览、在线搜索和 `PlayerBar`。

统一页面骨架：

```text
页面识别 / 上下文
标题 + 数量或状态
主操作带
工作面板
内容 / 空状态 / 加载状态 / 错误状态
```

音乐库和歌单保留用户熟悉的表格交互：单击浏览、双击播放、右键操作。只改善边界、密度、层级和信息对齐。

### 第三批：复杂流程和反馈

涉及：在线来源管理、失效歌曲恢复、在线候选选择、歌单 CRUD 弹窗、设置页、更新状态、空状态和错误反馈。

所有复杂流程统一为：

```text
明确标题
一句话说明当前任务
可滚动内容区
当前选择或风险提示
固定操作栏
```

操作完成、失败、部分成功和网络不可用都使用稳定的状态区域或轻量提示，不依赖窗口标题变化或颜色闪烁。

## 不改变的内容

- `QMediaPlayer`、播放队列、上一首/下一首和播放来源解析。
- `library.json`、`playlists.json`、`stats.json` 与用户设置的现有结构。
- 在线来源协议、来源启停、失效歌曲替换和在线更新流程。
- PyInstaller、Inno Setup、安装位置和正式发布产物。
- 旧 UI、用户数据、Git 历史和远端内容。

## 测试与验收

每一批都执行：

- 修改 Python 文件后逐文件 `py_compile`。
- UI v2 主题、壳层、页面和交互回归测试。
- `git diff --check` 与工作区状态核验。
- 深色与浅色主题检查。
- 900px、1200px、1440px 窗口尺寸检查。
- 鼠标点击、键盘 Tab、右键菜单、双击播放和当前播放高亮检查。
- 空状态、加载状态、错误状态、失效歌曲和网络不可用状态检查。

验收标准：用户不应在页面切换时感到视觉系统改变；不应看到无来源的暗绿、纯白或金色边框；主要操作能被立即找到；长时间浏览列表和播放时文字可读、控件稳定、内容不跳动。

## 回滚

每一批只修改主题、组件或对应页面，并创建独立本地提交。若视觉改动影响播放或布局，将回滚最近一批 UI 提交，不回滚用户数据、更新逻辑或历史提交。
