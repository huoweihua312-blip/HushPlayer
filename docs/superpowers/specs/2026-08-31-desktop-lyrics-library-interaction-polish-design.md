# HushPlayer 桌面歌词与资料库交互修正设计

## 1. 背景与目标

本次修正基于用户对当前 UI V2 实机截图的验收反馈，处理四个相互关联但边界清晰的问题：

1. 桌面歌词仍显示背景面板和歌曲标题，并在歌词更新时闪烁。
2. 歌曲表格双击时先弹出歌曲信息，遮断了双击播放体验。
3. “待导入”作为资料库一级导航挤占左侧空间，应并入设置。
4. 设置中的滑块仍呈现矩形底块，不符合透明、安静的视觉方向。

目标是恢复用户已经形成的交互习惯，简化桌面歌词视觉，并保持播放核心、歌词时间轴、导入数据、设置持久化和在线歌曲恢复逻辑不变。

## 2. 采用方案

采用局部修正方案，不重写桌面歌词、播放路由或设置中心：

- 在现有 `DesktopLyricsWindow` 内精简呈现层并合并高频刷新。
- 保留现有双击播放处理，只延后单击浏览动作，使系统双击判定能够取消信息弹窗。
- 复用现有 `PendingImportsPage` 和导入服务，将页面作为设置分类承载；主导航不再显示该入口。
- 只修改共享设置滑块的样式，不新增控件体系。

备选方案包括仅隐藏“待导入”入口后从设置跳转到旧页面，以及重写桌面歌词为自绘窗口。前者仍会在设置与主内容之间跳转，不算真正并入；后者会扩大歌词窗口风险。本轮不采用。

## 3. 桌面歌词设计

### 3.1 静态视觉

- 歌词窗口和歌词承载层均为完全透明，不绘制卡片背景、边框、圆角、阴影或标题区。
- 常态只显示当前歌词；不显示歌曲名、艺术家、状态标题或装饰信息。
- 支持一行主歌词，以及可选的第二行翻译或罗马音。
- 两行采用稳定的轻微错位：主歌词保持视觉居中，第二行在相同内容区域内向右偏移少量距离，避免机械式完全对齐，同时不得因文本长度改变窗口位置。
- 第二行字号和不透明度低于主歌词，保持清楚的主次关系。
- 颜色、开放字体、字号、不透明度、宽度和屏幕位置继续读取现有 `floating_lyrics_*` 设置。
- 开放字体白名单保持 Source Han Sans SC 和 Noto Sans SC，不加入系统字体选择或新的字体依赖。

### 3.2 空状态

- 没有当前歌曲、没有可显示歌词、歌词正在加载或歌词加载失败时，隐藏桌面歌词窗口，不显示“暂无歌词”等占位文字。
- 一旦出现有效当前歌词，若用户已开启桌面歌词，则恢复显示。
- 隐藏空状态不得改变“桌面歌词已开启”设置，也不得影响播放。

### 3.3 交互模式与工具栏

- 默认鼠标穿透、置顶和不抢焦点行为保持不变。
- 鼠标进入既有边缘热区后，临时显示紧凑工具栏，并允许拖动、打开歌词设置、归位、切换穿透和关闭。
- 工具栏与歌词承载层分离；仅工具栏在交互模式中可使用低干扰的半透明控件底色，以保证按钮可识别。退出交互模式后完全隐藏，不在歌词后方保留任何底板。
- 不增加持续动画。工具栏显示隐藏可以直接切换或使用短时透明度变化，但歌词文本更新不得触发窗口级动画。

### 3.4 防闪烁策略

- 播放、歌词文档、歌词状态和活动行信号先汇入一次事件循环级的合并刷新，避免同一状态连续重绘。
- 缓存当前已显示的主歌词、辅助歌词和可见状态；文本未变化时不重复调用标签更新。
- 常规歌词刷新不得调用 `show()`、`raise_()`、重新设置窗口标志、重新定位或重建控件。
- 只有用户主动显示/隐藏、有效歌词从无到有或交互模式真实变化时才改变顶层窗口状态。
- 切换鼠标穿透只在目标状态与当前状态不同时执行，避免反复重建原生窗口。

## 4. 单击浏览与双击播放

现有双击处理本身会请求播放，但表格的 `clicked` 信号先立即打开歌曲信息弹窗。修正后的行为为：

1. 单击普通歌曲单元格后，记录待浏览歌曲，并等待系统双击间隔。
2. 间隔结束且没有收到双击时，打开歌曲信息。
3. 同一行收到双击时，取消待执行的单击浏览，并立即沿用现有播放请求。
4. 收藏列和更多操作列继续只处理自身动作，不打开信息。
5. 缺失歌曲、在线恢复歌曲和只读状态继续沿用现有校验；在线恢复歌曲双击仍进入恢复流程。
6. Enter 键播放、右键“查看歌曲信息”和单击浏览习惯保持不变。

单击延迟使用 Qt 提供的系统双击间隔，不硬编码固定毫秒数。待执行的浏览只保存稳定歌曲 ID，不保存失效的模型索引。

## 5. 待导入并入设置

### 5.1 导航结构

- 主窗口左侧资料库区域不再显示“待导入”项目和数量，保留音乐库、浏览、在线搜索及现有歌单结构。
- 设置侧栏增加“待导入”分类；可在标题中显示当前数量，但不让数量改变侧栏宽度。
- 设置中的“音乐库”分类继续管理文件夹和扫描策略；“待导入”分类专门用于确认扫描结果，避免一个页面过度拥挤。

### 5.2 功能复用

- 复用现有 `PendingImportsPage`、`MusicFolderImportService` 和 `pending_imports.json`，不复制导入逻辑。
- 设置中的待导入页面保留全选、取消选择、加入音乐库、忽略和打开文件夹。
- `pending_changed` 继续实时刷新列表和数量；设置窗口关闭后服务连接仍保持稳定，不重复连接信号。
- 加入或忽略后的状态信息显示在设置中的待导入页面。
- 主内容路由可保留兼容代码，但正式导航不再创建或暴露待导入页面，避免旧链接影响现有数据。

### 5.3 错误处理

- 导入服务不可用时，设置分类显示正式空状态，不崩溃、不创建测试数据。
- 打开文件夹路径无效时保持现有失败返回，不修改或删除待导入记录。
- 忽略仍需要确认，且只移除待导入记录，不删除本地音频文件。

## 6. 设置滑块视觉

- `SliderSpinControl` 的控件背景、焦点背景和外框均为透明。
- 滑块只绘制细轨道、已完成进度和圆形手柄；不绘制覆盖整个滑块区域的矩形底块。
- 鼠标悬停只改变手柄或进度色，不改变控件背景。
- 禁用状态降低轨道和手柄对比度，但仍保持透明底。
- 键盘操作能力必须保留。键盘导航时以手柄描边或不带填充的细焦点提示表示焦点，不恢复矩形背景。
- 该样式作为共享控件同时应用于设置中心和歌词快捷设置中的同类滑块，数值范围和保存语义不变。

## 7. 数据与架构边界

本次不改变：

- `QMediaPlayer` 初始化、播放状态机、播放队列和上一首/下一首解析。
- 歌词解析、时间轴、同步算法、沉浸歌词页面和在线歌词逻辑。
- `library.json`、`playlists.json`、`stats.json` 和 `pending_imports.json` 的结构。
- 现有 `floating_lyrics_*` 设置字段及其兼容读取规则。
- Python、PySide6 或其他依赖版本。

允许增加仅用于 UI 调度的计时器、缓存字符串和设置分类连接，但不得复制播放器、歌词适配器或导入服务。

## 8. 自动检查与回归测试

实现后至少执行：

- 对所有修改的 Python 文件及 `main.py` 执行 `py_compile`。
- UTF-8 解码检查，并检查中文区域没有乱码。
- `git diff --check`、暂存区差异检查和最终 Git 状态检查。
- 桌面歌词测试：无背景和标题、单行/双行错位、空歌词隐藏、重复信号不重复重绘、穿透状态不反复切换。
- 歌曲表格测试：单击只打开一次信息、双击只播放且不打开信息、收藏/更多列不触发浏览、在线恢复分支保持。
- 设置测试：主导航无待导入入口、设置中可见待导入分类、记录和数量实时更新、导入/忽略/打开文件夹信号仍到达主窗口。
- 滑块测试：共享样式保持透明，无矩形焦点底，并保留数值变化信号。
- 运行现有播放、资料库、待导入、设置、桌面歌词、常规歌词和沉浸歌词相关回归测试。

## 9. 手动验收

1. 播放有歌词的歌曲并打开桌面歌词，确认屏幕上只有歌词文字，没有背景和歌曲标题。
2. 播放带翻译或罗马音的歌曲，确认最多两行且第二行轻微错位；长短歌词切换时位置不跳动。
3. 连续播放并拖动进度，观察歌词切换是否仍有闪烁。
4. 播放无歌词歌曲，确认桌面歌词隐藏；切回有歌词歌曲后自动恢复。
5. 在歌词常态下点击其他应用确认鼠标穿透；进入热区后确认工具栏可见、可拖动并能恢复穿透。
6. 单击歌曲确认稍后打开信息；双击歌曲确认立即播放且不出现信息弹窗。
7. 确认主窗口左侧不再显示待导入；打开设置中的“待导入”，完成选择、加入、忽略和打开文件夹操作。
8. 检查设置和歌词快捷设置中的滑块，确认只有细轨道与手柄，没有矩形底块。
9. 打开沉浸歌词并测试播放、暂停、切歌和进度同步，确认不受本次改动影响。

## 10. 回滚方式

本次实现应保持一个聚焦提交。若出现回归，可整体回滚该提交；待导入数据结构和设置字段均未迁移，因此回滚不会要求转换用户数据。若仅桌面歌词在特定 Windows 环境出现原生窗口问题，可优先回滚桌面歌词呈现与刷新部分，而保留双击、导航和滑块修正。
