# HushPlayer 设置密度、缓存位置与更新日志设计

日期：2026-08-13

## 目标

改善设置覆盖层在常用窗口尺寸下的视觉密度与中文可读性，并为用户提供缓存位置管理和应用内更新日志。改动必须保持现有播放、更新、歌单、音乐库和用户数据兼容。

## 设计决策

### 设置页面密度

- 保留现有设置侧栏和页脚结构，不重写设置架构。
- 设置区块使用统一的内容内边距、区块间距和行间距；操作按钮不再逐个占满整行。
- 缓存清理操作在宽屏横向排列，在窄窗口中使用可换行布局。
- 在线来源列表、缓存区块和关于区块使用一致的标题、说明、状态和操作层级。

### 缓存位置

- 新增兼容字段 `cache_directory`，空值表示沿用系统默认缓存目录。
- 用户只能选择已有目录；保存前验证目录存在且可写。
- 运行时优先级为环境变量 `HUSHPLAYER_CACHE_DIR`、设置中的 `cache_directory`、系统默认目录。
- 改变缓存位置不自动迁移、复制或删除旧缓存；提示用户重启后生效，降低数据丢失和运行中服务切换风险。
- “恢复默认”只清除设置字段，不清理任何旧目录。

### 关于与更新日志

- 关于页保留应用名称、版本和 Logo。
- 新增只读滚动更新日志，读取仓库正式 `CHANGELOG.md` 的版本章节。
- 只展示已发布版本内容，过滤 `## 未发布`，无法读取时显示明确的降级提示。

### 字体与可读性

- 继续使用已内置并附带许可证的 Noto Sans SC。
- 设置标题、分组标题、按钮、状态徽章使用更明确的 600/700 字重；正文和辅助信息保持层级差异，不通过缩小字号解决拥挤。
- 所有新增控件保留可见键盘焦点、工具提示和可读的禁用状态。

## 数据流与边界

设置控件只读写 `SettingsSnapshot`，不直接操作 JSON。`LegacySettingsBridge` 负责默认值、校验和原子保存；`AppPaths.resolve()` 在启动构建正式运行时读取缓存目录设置。当前进程不热切换缓存服务，保存后提示重启。

## 验证

- 设置旧 JSON 不含 `cache_directory` 时仍能读取并使用默认路径。
- 自定义目录保存、恢复默认、无效目录拒绝和未知设置字段保留。
- 更新日志显示正式版本，隐藏未发布章节。
- 设置页在宽屏和窄窗口下不出现连续挤压按钮或水平滚动。
- 运行现有设置、在线搜索、来源管理、音乐库和主窗口回归测试。
