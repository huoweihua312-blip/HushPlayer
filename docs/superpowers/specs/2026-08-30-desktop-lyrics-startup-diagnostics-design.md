# HushPlayer 启动诊断与桌面歌词方案 A 设计

## 1. 背景与目标

本次工作包含两个相互独立但都影响“第一次使用感受”的改进：

1. 找出启动过程卡顿的真实来源，并让非首屏必要工作不再阻塞主窗口第一次绘制。
2. 在现有播放适配器和歌词适配器之上增加桌面歌词入口。桌面歌词默认鼠标穿透，进入边缘热区后可交互、可拖动并显示小工具栏，同时支持歌词颜色、位置、开放字体和字体大小设置。

目标是降低首屏等待和启动卡顿，同时保持现有播放、播放队列、歌词同步、沉浸歌词和设置文件兼容，不引入第三方依赖，不复制第二套播放器。

## 2. 已确认的交互约束

- 播放栏增加“桌面歌词”按钮；按钮只负责显示/隐藏桌面歌词窗口，不改变当前播放歌曲。
- 桌面歌词是独立顶层窗口，可悬浮在其他应用上方。
- 默认开启鼠标穿透，歌词不会拦截用户对其他窗口的点击。
- 鼠标进入窗口边缘热区，或使用桌面歌词快捷键时，临时进入交互模式并显示小工具栏。
- 交互模式支持拖动窗口、打开设置、切换鼠标穿透、重置位置和关闭窗口。
- 鼠标离开热区且短时间没有操作后，恢复鼠标穿透；工具栏隐藏。
- 歌词设置支持颜色、屏幕位置/拖动位置、字体、字体大小、透明度等现有能力的统一入口。
- 桌面歌词字体下拉列表只暴露随应用分发且具有开放授权的字体：Source Han Sans SC、Noto Sans SC。系统字体只作为内部回退，不作为可选项展示。
- 没有当前歌词、歌词加载失败或歌曲切换时，窗口显示低干扰的空状态，不阻塞播放。

## 3. 方案与边界

### 3.1 启动诊断与优化

在 `app/startup.py` 和 `app/ui_v2/startup.py` 增加轻量阶段计时，覆盖：

- QApplication 和进程级环境初始化
- 主题、设置与内置字体加载
- 运行时服务构造，包括在线发现服务和播放适配器
- MainWindow 构造
- 窗口第一次 show 到首个可绘制状态
- 音乐库快照加载、后台扫描、非必要页面/推荐数据初始化

计时采用单调时钟，输出到现有应用日志目录，包含阶段耗时和总耗时。日志不记录歌曲文件内容、用户路径之外的敏感信息或网络凭证。诊断逻辑必须是低成本的；若日志不可写，不影响启动。

启动顺序调整为：

1. 完成最小 UI 和播放器连接，尽快显示主窗口。
2. 将音乐库刷新、推荐/在线发现的非必要初始化和启动扫描保持在后台或首屏之后调度。
3. 继续使用已有 `RealLibraryAdapter`、导入服务和 QThread 机制，不重写线程架构。
4. 对窗口构造阶段只做必要的延迟化，先测量再改变具体阶段；不能用“延迟”掩盖真正的同步阻塞。

诊断日志需要能回答“哪个阶段最慢”，并在同一次启动中区分主线程阶段和后台任务开始时间。首轮实现不自动上传日志，也不增加诊断服务器。

### 3.2 桌面歌词窗口

新增独立的 `DesktopLyricsWindow`，职责仅限于桌面歌词的呈现、窗口交互和设置同步：

- 依赖现有 `PlaybackAdapter` 和 `LyricsAdapter`，不创建新的 `QMediaPlayer`、队列或歌词解析器。
- 订阅当前曲目、播放状态、歌词文档和当前位置更新；只更新必要的文本和高亮状态。
- 使用无边框、半透明、置顶工具窗口。视觉风格采用安静的深色半透明卡片、清晰的主/辅歌词层级、轻边框和柔和阴影，不使用大面积炫光或持续动画。
- 窗口保留最小可读宽高，字号改变时重新计算布局但不允许窗口缩小到裁切主歌词。
- 位置设置采用“拖动后保存坐标 + 重置到当前屏幕安全区域”的方式。跨屏或分辨率变化时将坐标限制在可见工作区内。
- 设置面板使用现有设置桥接；新增字段必须有默认值，旧版 `settings.json` 缺字段时使用默认值并继续运行。
- 颜色使用现有颜色预设保持兼容；若后续加入自定义颜色，必须使用严格的颜色值校验并保留非法旧值的安全回退。

### 3.3 鼠标穿透实现

交互模式是桌面歌词的核心风险点，按以下状态设计：

```text
穿透模式
  ├─ 鼠标进入窗口边缘热区 / 快捷键
  ↓
交互模式 + 工具栏可见
  ├─ 拖动、设置、重置、关闭
  ├─ 点击“保持交互”则不自动退出
  └─ 无操作并离开热区
  ↓
穿透模式
```

窗口在穿透状态下不依赖 hover 事件判断自身进入；使用低频、可停止的光标位置轮询判断热区，避免因 `WindowTransparentForInput` 导致无法收到鼠标事件。切换窗口输入属性时要避免反复重建窗口、闪烁或夺取焦点；如平台 API 细节在当前 Qt 版本不稳定，优先保留显式快捷键和工具栏切换作为可靠后备，不改变主窗口输入行为。

快捷键只作为辅助入口，默认使用不会与现有播放器快捷键冲突的组合，并在设置/工具提示中明确显示。快捷键注册失败时不影响主程序启动。

## 4. 设置字段与兼容性

在现有 `floating_lyrics_*` 命名下增加最小字段集合：

- `floating_lyrics_font_family`：默认 `Source Han Sans SC`
- `floating_lyrics_x`、`floating_lyrics_y`：默认未定位状态，首次显示按当前屏幕安全区域居中或底部居中
- `floating_lyrics_height`：提供安全默认值，兼容已有整数校验
- `floating_lyrics_passthrough`：默认 `true`

已有颜色、透明度、字号、宽度和自动打开字段保持原名和读取规则。未知字段继续保留，保存设置时不覆盖其他模块字段。窗口位置只保存为整数，不保存屏幕设备名称，防止显示器变化后永久跑到不可见区域。

## 5. 错误处理

- 桌面歌词窗口创建失败：主窗口继续可用，并以非阻塞提示说明桌面歌词无法打开。
- 歌词为空或加载失败：显示歌曲名/艺术家和“暂无歌词”，不抛出未处理异常。
- 字体加载失败：回退到内置开放字体，再回退到主题字体族；设置界面仍只显示允许的开放字体。
- 屏幕坐标失效：按当前屏幕工作区夹紧到可见区域。
- 快捷键冲突或注册失败：记录诊断日志，保留播放栏按钮和边缘热区入口。
- 启动阶段计时/日志失败：静默降级，不影响原启动路径。

## 6. UI 设计验收点

- 播放栏按钮与现有歌词按钮视觉一致，有清晰 tooltip 和激活状态。
- 桌面歌词默认不抢焦点、不挡点击；可通过热区或快捷键可靠进入交互。
- 工具栏只在需要时出现，按钮具备文字/tooltip、最小可点击尺寸和键盘可达性。
- 主歌词与翻译/罗马音有明显层级，颜色与背景对比足够；字号最小值不低于可读阈值。
- 设置项有明确标签、当前值反馈和恢复默认入口，不依赖 hover 才能理解。
- 动画仅用于工具栏淡入淡出和状态切换，控制在短时长内；不对每次歌词位置更新执行重型动画。
- 深色主题下不使用纯黑大块背景，保留边界和焦点可见性。

## 7. 测试与验收

### 自动检查

- 对所有修改或新增 Python 文件执行 `py_compile`。
- 执行 `git diff --check` 和暂存区检查。
- 增加设置字段默认值、旧设置读取、位置夹紧和字体白名单的单元级覆盖。
- 增加桌面歌词状态切换/显示隐藏/关闭不影响播放适配器的测试。
- 增加启动阶段计时在日志不可写或阶段异常时不阻断启动的测试。
- 运行已有播放、歌词、沉浸歌词、设置、主窗口和主题相关回归测试；若环境缺失 PySide6，只报告语法检查结果与未执行的运行时测试。

### 手动验收

1. 冷启动 3 次，查看日志中的阶段耗时，确认能定位最慢阶段，并观察首个主窗口是否先出现再加载库。
2. 播放歌曲，点击“桌面歌词”，确认窗口显示当前歌词且播放不中断。
3. 将鼠标直接点击其他应用，确认默认穿透；进入歌词窗口边缘后确认工具栏出现并可拖动。
4. 修改颜色、字体、字号、透明度和位置，关闭再打开应用，确认设置保留且字体仍仅为两种开放字体。
5. 切换歌曲、暂停、拖动进度、无歌词歌曲和歌词加载失败场景，确认窗口不崩溃、不创建第二个播放器。
6. 移动/禁用副显示器或改变缩放，确认窗口不会永久跑出屏幕。
7. 打开沉浸歌词页面，确认它仍使用原页面形态和原播放/歌词同步，不被桌面歌词窗口抢焦点或改写。

## 8. 非目标与回滚

本次不做：

- 新增第三方依赖或独立 Node/播放进程
- 重写播放核心、歌词解析器、队列和音乐库数据结构
- 自定义字体文件导入、在线字体下载或系统字体管理
- 自动上传启动诊断信息
- 全面拆分 `main_window.py` 或替换现有 UI 架构

回滚方式：删除本次新增的桌面歌词窗口/启动诊断改动，恢复播放栏到原歌词入口；新增设置字段属于向后兼容字段，旧版本会忽略，不需要迁移 `library.json`、`playlists.json` 或 `stats.json`。实现阶段将保持每个提交聚焦，以便只回滚桌面歌词或只回滚启动优化。
