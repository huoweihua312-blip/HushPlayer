# HushPlayer 桌面歌词右键快捷设置设计

## 1. 背景与目标

当前桌面歌词设置集中在主设置页的“歌词”分类中。用户实机测试发现两个直接问题：

1. 桌面歌词字号调整不能提供可信、即时的视觉反馈。
2. 桌面歌词设置区域层级偏重，和“随手调整悬浮歌词”的使用场景不匹配。

本轮目标是把桌面歌词设置从主设置页移到播放器底栏“桌面歌词”按钮的右键快捷浮层中，同时修正字号单位和应用链路。左键开关、桌面歌词透明呈现、鼠标穿透、拖动、歌词同步和沉浸歌词均保持现有语义。

## 2. 采用方案

采用按钮锚定的紧凑 Fluent 浮层：

- 左键“桌面歌词”按钮继续显示或隐藏桌面歌词。
- 右键同一按钮打开或关闭快捷设置浮层。
- 桌面歌词设置只保留这一处正式入口；主设置页移除“桌面歌词”区。
- 控件修改立即预览，并在停止操作约 250 ms 后自动保存。
- 桌面歌词未显示时只更新并保存设置，不自动开启歌词。

不采用传统多级 `QMenu`，因为它不适合承载滑块、字体预览和颜色选择；也不采用独立设置窗口，因为它会打断播放场景并增加窗口管理负担。

## 3. 交互设计

### 3.1 左键与右键分工

- 左键行为不变：切换桌面歌词的逻辑启用状态，不切换主页面。
- 右键只打开快捷设置，不触发左键，不改变桌面歌词启用状态。
- 右键入口在桌面歌词窗口尚未创建时也可使用；浮层从现有设置快照初始化。
- 再次右键、点击浮层外部或按 `Esc` 关闭浮层。
- 浮层打开期间不抢占播放快捷键，不改变当前歌曲、浏览状态或播放上下文。

### 3.2 快捷设置内容

浮层按以下稳定顺序显示：

1. 歌词颜色：白、黑、黄、蓝、绿、粉、紫七个现有选项。
2. 歌词字体：仅显示 `OPEN_FONT_FAMILIES` 中随应用分发且具有开放授权的字体。
3. 字号：22–84 px，显示固定宽度数值。
4. 不透明度：20%–100%。
5. 显示宽度：420–1600 px。
6. 默认鼠标穿透开关。
7. “恢复默认位置”次要操作。

位置继续通过拖动桌面歌词调整并自动持久化，不新增横纵坐标输入框。“恢复默认位置”将窗口放回当前屏幕底部中央，并沿用现有坐标保存逻辑。

### 3.3 即时预览与自动保存

- 每次控件变化先合并到内存中的设置快照，并立即调用现有桌面歌词窗口的 `apply_settings()`。
- 若桌面歌词当前可见，颜色、字体、字号、不透明度和宽度应在同一次交互中可见变化。
- 若桌面歌词未显示，变化只更新快照并保存，下次显示时生效；不得为了预览自动打开歌词。
- 连续拖动滑块时重启一个约 250 ms 的单次计时器；计时结束后通过现有 `LegacySettingsBridge` 校验和保存。
- 离散操作（颜色、字体、穿透开关、恢复位置）同样使用统一的短防抖保存路径，避免出现两套持久化语义。
- 不显示“保存”或“取消”按钮。自动保存成功后保持安静，不弹出提示。

### 3.4 保存失败

- 保存失败时，在浮层底部显示一行简短错误，不弹出模态对话框。
- 恢复最近一次成功保存的设置快照，并重新应用到桌面歌词窗口。
- 保存错误不得关闭桌面歌词、影响播放或修改歌词时间轴。
- 所有输入值在进入预览和保存前按现有合法范围归一化；开放字体以外的值回退到默认开放字体。

## 4. 视觉设计

浮层使用单层 Quiet Orbit / Fluent 面板，参考布局：

```text
桌面歌词                         ×

颜色     ○ ○ ○ ○ ○ ○ ○
字体     [ Source Han Sans SC  ▾ ]

字号     ─────●────────   42 px
透明度   ─────────●────   90%
宽度     ───────●──────   980 px

[✓] 鼠标穿透
[恢复默认位置]
```

视觉约束：

- 宽度约 340 px，并根据主窗口可用范围夹紧位置；优先锚定在按钮上方。
- 只绘制一层圆角背景、细边框和克制阴影，不嵌套多层卡片。
- 滑块控件背景、焦点背景和外围矩形边框保持透明，只显示细轨道、进度和圆形手柄。
- 颜色选项使用圆形色点；当前项使用高对比描边和非纯颜色的选中标记，避免只依赖颜色表达状态。
- 数值标签固定宽度，字号、宽度和透明度变化时不移动其他控件。
- “恢复默认位置”使用次要文字按钮，不使用危险色。
- 使用当前主题 token 支持深浅主题，不建立第二套硬编码配色。
- 打开可以使用 120–160 ms 的轻微淡入；系统减少动画或应用减少动画设置启用时直接显示。
- 桌面歌词文字窗口继续完全透明，不因快捷设置浮层重新出现背景、标题或装饰层。

## 5. 组件与职责

### 5.1 `PlayerIconButton` / `PlayerBar`

- 为桌面歌词按钮增加独立右键请求信号。
- 左键现有 `desktop_lyrics` 动作连接保持不变。
- 右键事件必须被接受，不能继续传播为左键或触发显示/隐藏。

### 5.2 `DesktopLyricsQuickSettingsPopover`

新增独立轻量 UI 组件，建议放在 `app/ui_v2/widgets/desktop_lyrics_quick_settings.py`：

- 负责控件布局、主题、锚定定位、键盘关闭和外部点击关闭。
- 接收设置快照，不直接读取或写入 `settings.json`。
- 发出字段更新、恢复位置和关闭请求。
- 复用现有主题、开放字体列表、设置滑块样式和必要的通用控件；不得复制设置持久化逻辑。

### 5.3 `MainWindow`

- 缓存一个快捷设置浮层实例，避免每次右键重复创建和重复连接。
- 将当前 `_settings_snapshot` 传入浮层。
- 接收字段变化，先生成更新后的快照并即时预览，再通过防抖保存。
- 保存成功后替换 `_settings_snapshot`；失败时回退并通知浮层。
- 连接恢复位置请求到现有 `DesktopLyricsWindow.reset_position()`。若窗口尚未创建，可先创建但保持逻辑禁用和不可见。

### 5.4 `DesktopLyricsWindow`

- 继续通过 `apply_settings()` 接收完整设置，不直接持久化外观字段。
- 将主歌词字体改为 `QFont.setPixelSize()`；辅助歌词按现有比例从像素字号派生。
- 保留颜色、透明度、宽度、位置、穿透、无背景、最多两行和防闪烁逻辑。
- 悬浮工具栏移除“设置”按钮，保留“归位、穿透、关闭”。

### 5.5 主设置页

- “歌词”分类保留全部沉浸歌词设置。
- 删除桌面歌词的颜色、字体、透明度、字号、宽度和穿透控件。
- 不删除底层 `floating_lyrics_*` 字段、默认值、校验或兼容读取逻辑，因为快捷浮层继续使用这些正式字段。

## 6. 数据流

```text
右键桌面歌词按钮
        ↓
读取 MainWindow 当前 SettingsSnapshot
        ↓
打开/同步 DesktopLyricsQuickSettingsPopover
        ↓ 控件变化
生成归一化后的工作快照
        ├─→ DesktopLyricsWindow.apply_settings() 即时预览
        └─→ 250 ms 防抖 → LegacySettingsBridge.save_snapshot()
                              ├─ 成功：替换正式快照
                              └─ 失败：显示行内错误并恢复上次正式快照
```

任何一步都不得重建播放器、改变播放 source、修改队列或重新解析歌词。

## 7. 数据与兼容边界

本轮不新增第三方依赖，不新增设置字段，也不改变以下持久化结构：

- `data/library.json`
- `data/playlists.json`
- `data/stats.json`
- `data/settings.json` 的现有字段结构

现有 `floating_lyrics_color`、`floating_lyrics_opacity`、`floating_lyrics_font_size`、`floating_lyrics_width`、`floating_lyrics_height`、`floating_lyrics_font_family`、`floating_lyrics_x`、`floating_lyrics_y` 和 `floating_lyrics_passthrough` 字段继续兼容读取。未知设置字段必须在保存时保留。

本轮不修改：

- `QMediaPlayer` 和 `QAudioOutput` 初始化或状态管理。
- 播放上下文、播放队列、上一首/下一首和播放模式。
- 歌词解析、歌词活动行判定、时间轴和同步逻辑。
- 沉浸歌词页面及其字号设置。
- 音乐库、待导入、歌单、在线来源和缓存行为。

## 8. 自动检查与回归测试

实现后至少执行：

- 对 `main.py` 及所有修改或新增的 Python 文件执行 `py_compile`。
- 对含中文的修改文件执行 UTF-8 解码检查，并搜索明显乱码。
- `git diff --check`、暂存区差异检查和最终 Git 状态检查。
- 左键测试：单击桌面歌词按钮仍只切换显示状态。
- 右键测试：只打开快捷设置，不改变桌面歌词启用状态或主页面路由。
- 浮层测试：从快照同步全部控件，位置锚定不超出可用范围，`Esc` 和再次右键可关闭。
- 字号测试：22 px 与 84 px 产生不同的 `QFont.pixelSize()`，调整时立即应用，不等待保存。
- 自动保存测试：连续滑块变化只触发一次防抖保存，成功后更新正式快照。
- 失败测试：持久化失败时恢复上次快照并显示行内错误。
- 字体测试：只接受开放字体白名单，非法字体回退。
- 设置页测试：歌词分类不再创建桌面歌词控件，沉浸歌词控件仍存在。
- 桌面歌词回归：无背景、最多两行、空歌词隐藏、位置持久化、穿透切换和重复渲染抑制保持。
- 运行现有播放器按钮、设置、桌面歌词、常规歌词和沉浸歌词相关测试。

## 9. 手动验收

1. 左键底部“桌面歌词”，确认仍只负责显示和隐藏。
2. 右键该按钮，确认浮层出现在按钮上方，且没有切换页面或改变播放。
3. 把字号从最小拖到最大，确认桌面歌词立即、明显改变，显示数值与实际像素字号一致。
4. 连续拖动字号、透明度和宽度，确认界面流畅，停止后自动保存且没有弹窗。
5. 调整颜色和开放字体，确认桌面歌词实时变化；重新启动应用后设置仍保留。
6. 隐藏桌面歌词后右键调整，再重新显示，确认新设置生效且调整过程没有擅自打开歌词。
7. 测试鼠标穿透、边缘交互、拖动、归位和关闭，确认既有交互未回归。
8. 点击浮层外、按 `Esc`、再次右键按钮，确认都能关闭浮层。
9. 打开主设置页的“歌词”分类，确认只剩沉浸歌词设置。
10. 播放、暂停、切歌、拖动进度并打开沉浸歌词，确认播放与歌词同步不受影响。

## 10. 回滚方式

设计和实现分别使用聚焦提交。若实现出现回归，可整体回滚实现提交；由于没有新增字段或迁移数据，回滚不需要转换 `settings.json`。若仅右键浮层存在窗口定位问题，可优先回滚浮层接线，同时保留独立的像素字号修复。
