# 主题切换即时反馈修复设计

## 背景

当前点击标题栏深浅色按钮后，主题揭示遮罩会先出现短暂停顿，再开始圆形扩散动画。问题来自主题切换入口在动画启动前同步执行了窗口截图、设置保存、全局样式刷新和多个组件换肤。此前的性能提交虽然把部分操作拆成了事件循环批次，但全局样式仍位于动画启动之前。

## 目标

1. 点击主题按钮后尽快显示并启动现有圆形揭示动画。
2. 将设置保存和主题样式应用安排到后续事件循环，不阻塞按钮点击返回。
3. 保留当前主题揭示视觉效果、浅色/深色主题一致性和设置持久化行为。
4. 不改变播放、播放队列、歌词、桌面歌词、沉浸歌词或持久化 JSON 结构。

## 方案

### 点击反馈与调度

`MainWindow._queue_theme_reveal_apply()` 负责创建遮罩并立即启动动画，然后只负责安排后续主题应用。主题应用回调不再重复启动动画；这样第一次动画帧可以在 Qt 返回事件循环后及时绘制。

窗口截图仍使用现有 `ThemeRevealOverlay` 所需的快照，不改变遮罩的绘制方式或动画时长。主题按钮在切换期间继续禁用，避免并行创建多个遮罩。

### 主题应用

后续回调保存目标设置快照，并调用现有 `_apply_settings_snapshot()`。`set_theme()` 继续更新应用调色板、根窗口样式、页面样式、标题栏、播放器栏、设置界面和可见歌词窗口；已存在的分阶段组件刷新机制继续负责降低单次刷新压力。

如果设置保存或主题应用失败，沿用现有错误提示和遮罩清理逻辑，恢复主题按钮可用状态，不让主窗口停留在禁用更新状态。

## 数据流

```text
点击主题按钮
    -> 创建窗口快照
    -> 显示遮罩并立即启动动画
    -> 返回 Qt 事件循环，绘制首帧
    -> 保存目标设置并应用主题
    -> 分阶段刷新组件
    -> 动画完成后清理遮罩并恢复按钮
```

设置文件仍通过 `LegacySettingsBridge.save_snapshot()` 写入，字段和兼容行为保持不变。

## 验证

- 运行 Python 语法检查和现有主题相关 UI 测试。
- 验证点击后遮罩动画已经启动，且主题最终切换完成。
- 验证连续点击、打开设置页切换主题、关闭窗口和无音乐库场景不会残留遮罩或锁定按钮。
- 验证播放、歌词和桌面歌词相关对象没有被重建。
- 进行一次可见窗口手动测试，重点观察点击到第一帧动画之间是否仍有明显停顿。

## 风险与回滚

主要风险是动画已经开始后，后续样式刷新仍可能造成中途短暂掉帧；本次只调整调度顺序，不重写主题系统。若出现主题未完成、遮罩残留或组件颜色不一致，可回退本次主题切换代码改动，恢复原有同步应用路径。
