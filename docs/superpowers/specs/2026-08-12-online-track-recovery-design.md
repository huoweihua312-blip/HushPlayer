# 在线恢复失效歌曲播放设计

## 背景

歌单和“我喜欢”中可能保留本地文件已经失效，或在线来源已经无法播放、但仍有完整歌曲名和歌手信息的歌曲记录。当前双击这类歌曲不会播放，用户也需要手动进入在线搜索页重新输入关键词。

本次目标是让正常在线歌曲先按普通在线播放链路直接播放；当真实播放确认失败时，自动使用已启用来源寻找匹配版本，并通过新的来源覆盖恢复原歌曲。用户仍可通过“在线寻找并播放”手动重试。

## 范围与不变项

- 只处理用户主动触发的单首歌曲。
- 仅搜索当前已启用且支持搜索的在线来源。
- 不下载歌曲，不绕过登录、会员、DRM、地区限制或平台访问控制。
- 不删除原歌曲记录、歌曲 ID 或本地文件；仅在用户选定在线版本后保存在线播放来源覆盖。
- 匹配成功时仅为原歌曲记录保存在线播放来源覆盖，不改变我喜欢、普通歌单、歌曲 ID、顺序或加入时间。
- 播放队列沿用原歌曲身份，但将解析请求路由到覆盖来源；原歌曲元数据仍用于列表和播放器展示。
- 单击歌曲仍只浏览；正常可播放歌曲的双击行为保持不变。
- 播放全部和随机播放仍跳过失效歌曲，不自动批量触发在线搜索。
- 自动恢复只针对当前单首歌曲；同一播放上下文最多自动尝试一次，不会因失败来源循环搜索。

## 推荐方案

新增独立的一次性在线恢复解析器，不复用在线搜索页当前查询状态。解析器通过现有统一在线搜索能力异步查询，避免清空或覆盖用户正在查看的在线搜索结果。

### 触发入口

1. `TrackTable` 只对本地文件缺失或已确认在线播放失败的歌曲双击触发恢复请求。
2. 尚未解析 (`not_resolved`) 的正常在线歌曲双击走普通 `play_requested` 路径，不弹候选框。
3. 真实音乐库在线歌曲在普通播放流程收到确认失败状态后，由 `MainWindow` 自动触发一次恢复请求。
4. 已确认失效歌曲右键菜单增加“在线寻找并播放”；正常在线歌曲不显示该入口。

### 查询与匹配

- 查询词由歌曲名和歌手组成；缺少歌手时只使用歌曲名。
- 对标题、歌手、专辑、时长做规范化比较：大小写、空白和常见标点差异不影响匹配。
- 标题完全匹配权重最高，其次是标题包含、歌手完全匹配、歌手包含、专辑匹配和时长接近。
- 只有达到最低置信度且明显领先第二名的候选才自动播放。
- 多个候选分数接近时，显示候选选择对话框，不静默播放不确定结果。
- 没有候选或所有候选都低于阈值时，提示未找到可靠在线版本。

### 播放与状态

- 匹配成功的 `OnlineTrack` 转为现有在线 `Track` 投影，交给已有 `OnlineAdapter`/`online_play_requested` 播放路径。
- 选择成功后只在原远程记录中保存 `playback_source` 覆盖，不替换歌单成员；播放队列保持原歌曲稳定身份。
- 播放来源失败时不改变原歌曲、收藏和歌单，允许再次选择其他来源。
- 自动恢复失败时不阻塞页面；原歌曲保留在音乐库中，用户可从右键菜单手动再次搜索。
- 恢复搜索期间显示非阻塞状态提示，搜索不会冻结主界面。
- 成功提示包含来源名称；失败提示说明未找到可靠匹配或在线来源不可用。

## 组件边界

- `TrackTable`：只负责识别失效歌曲触发和菜单呈现，不实现网络搜索。
- `TrackListPage`/`ContentRouter`：转发恢复播放请求，保持页面和播放上下文边界清晰。
- `OnlineTrackRecoveryService`：负责一次性异步查询、候选规范化、评分和结果信号。
- `MainWindow`：接收恢复结果，调用 `OnlineAdapter` 保存来源覆盖并复用现有在线播放入口。
- `MainWindow`：接收真实播放失败状态，只对音乐库中的当前在线歌曲启动一次自动恢复，并按稳定 ID 防止循环。
- 现有 `OnlineAdapter`、`PlaybackAdapter` 和远端来源协议：保持原有播放、来源和错误处理契约。
- `RealLibraryAdapter`：对历史 `replaced_by` 记录建立内存别名，将旧歌曲 ID 作为显示、收藏和歌单身份，并把旧目标记录作为播放来源；不自动重写用户歌单文件。

## 失败与并发处理

- 每次恢复请求拥有独立 generation；用户切换页面或再次触发时，旧结果不能覆盖新请求。
- 在线来源失败、超时、无启用来源和无可靠候选都只产生提示，不改变原歌曲数据；持久化替换失败时原歌单关系保持不变。
- 自动恢复只响应 `source_unavailable`、`resolve_failed`、`permission_denied` 和 `playback_error` 等确认失败状态，不响应 `not_resolved` 或普通缓冲状态。
- 历史旧替换记录只在内存中兼容映射；来源覆盖成功后仍保留旧字段，避免刷新时歌曲消失。
- 恢复请求不取消用户已经进行的普通在线搜索。
- 用户关闭或退出应用时，未完成的恢复请求安全丢弃。

## 测试计划

- 单元测试：标题/歌手/专辑/时长规范化和候选评分。
- 单元测试：唯一高置信度候选自动选中；低置信度和并列候选不自动播放。
- UI 测试：失效歌曲双击发出恢复请求；右键菜单显示恢复入口；正常歌曲路径不变。
- UI 测试：`not_resolved` 正常在线歌曲双击直接播放且不显示恢复入口。
- 回归测试：来源覆盖保留歌单位置和加入时间，音乐库独有远程记录也能使用；替换失败不删除歌单、不改变收藏关系。
- 回归测试：历史 `replaced_by` 记录恢复为原歌曲身份，目标记录不造成重复或消失。
- 播放链路测试：恢复成功的在线投影进入现有在线播放路径。
- 主窗口回归测试：音乐库在线歌曲收到确认失败状态后只自动请求一次恢复；同一身份的后续失败不会循环触发。
- 构建后手动测试：在“我喜欢”和普通歌单中分别验证失效歌曲的双击、右键恢复、取消操作和失败提示。

## 回滚

实现集中在恢复入口、独立解析器、成员替换桥接层和主窗口转发层。若匹配准确性或在线来源兼容性不满足验收，可回滚本次提交；已发生的用户替换关系可通过重新将原歌曲加入歌单恢复，原歌曲记录和本地文件始终保留。
