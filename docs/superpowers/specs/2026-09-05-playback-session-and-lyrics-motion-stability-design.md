# 播放会话恢复与歌词动效稳定性设计

## 背景

当前设置中已经提供“恢复上次会话”开关，但正式启动流程没有读取或恢复播放会话。因此应用重新启动后会丢失上次歌曲、播放进度、播放队列和浏览页面，并回到未选择歌曲的状态。

桌面歌词虽然已经对拖动期间的尺寸变化做过延后处理，但切句时仍按当前两行文本重新测量顶层窗口，并可能连续执行 `resize()` 与中心位置校正。歌词长度变化、拖动结束和延后布局同时发生时，仍可能造成位置跳动。

沉浸式歌词使用一个自绘画布。当前行改变时，画布会立即以新歌词为中心重新绘制全部可见行，没有行间过渡，因此视觉上表现为闪现而不是滚动。

## 已确认体验

1. 重新启动后恢复上次歌曲、播放位置、有效队列和浏览页面。
2. 恢复后保持暂停，等待用户点击播放，不自动出声。
3. 如果上次停留在沉浸模式，启动时恢复到普通歌词页，不自动进入全屏或透明沉浸状态。
4. 桌面歌词继续只显示两行，并保留长歌词完整显示、拖动、锁定、穿透、右键设置等现有行为。
5. 沉浸歌词相邻切句采用短距离纵向滑动；跨越多句、切歌或手动大幅跳转时直接定位。
6. 开启“减少动画”后，沉浸歌词不播放切句滑动。

## 目标

- 让“恢复上次会话”成为真实可用且向后兼容的功能。
- 恢复歌曲时不采用“先播放再暂停”，杜绝启动时短暂出声。
- 消除桌面歌词因自动测量、切句和拖动竞争产生的位置跳动。
- 让沉浸歌词切句保持空间连续性，同时不影响逐字高亮和播放同步。
- 不改变音乐库、歌单、统计信息和设置文件的既有结构。
- 不增加第三方依赖，不重写播放器或歌词架构。

## 非目标

- 不自动继续播放。
- 不恢复沉浸全屏、透明窗口或临时弹出面板状态。
- 不修改歌词时间轴解析、匹配或在线歌词请求逻辑。
- 不改变上一首、下一首、随机播放和循环模式的既有语义。
- 不迁移 `library.json`、`playlists.json` 或 `stats.json`。
- 不为这次修复拆分 `main_window.py` 或替换 `QMediaPlayer`。

## 方案

### 1. 独立、容错的播放会话文件

使用应用数据目录中已经预留的 `playback_session.json`，以带版本号的独立文档保存：

- 当前歌曲的稳定标识；
- 当前队列中歌曲的稳定标识顺序；
- 播放位置；
- 当前浏览路由；
- 最后更新时间。

会话写入采用临时文件替换，避免中途退出产生半截 JSON。播放位置变化不会每次都立即写盘，而是通过低频定时合并保存；切歌、队列变化和路由变化会标记待保存，真正退出时再强制写入一次。最小化到托盘不视为退出，不清空也不重复恢复会话。

文件缺失、损坏、字段类型错误或版本未知时直接忽略并记录诊断，不阻止应用启动。旧版本不会读取这个新文件，因此回滚应用版本不会破坏原有数据。

### 2. 延后到真实音乐库加载后恢复

正式版音乐库在后台加载，恢复不能发生在空队列阶段。启动时只读取并暂存会话；音乐库及已保存的在线歌曲投影完成后，再按稳定标识解析有效歌曲：

1. 过滤已经不存在或不可识别的歌曲；
2. 重建仍然有效的队列；
3. 选中上次歌曲但不播放；
4. 媒体可以定位后恢复进度；
5. 恢复有效浏览路由。

若当前歌曲失效，则不擅自播放队列中的其他歌曲；界面安全回退到无当前歌曲状态。若保存路由对应的歌单已经删除，则回退到音乐库。沉浸路由统一恢复为普通歌词页，避免启动即进入全屏体验。

### 3. 播放器增加“准备歌曲”路径

在现有播放控制器和适配器中增加一个小范围的“准备/选择歌曲”入口：

- 本地歌曲只设置媒体源、当前歌曲和时长上下文，不调用播放；
- 在线歌曲只恢复当前歌曲上下文，等用户点击播放时再解析在线地址；
- 恢复过程中始终向 UI 发布正常的歌曲、时长和暂停状态；
- 对尚未可定位的本地媒体暂存目标进度，在媒体加载到可定位状态时只应用一次。

不使用现有 `play_item()` 后立刻 `pause()` 的办法，因为它可能产生短暂声音、在线解析和不必要的播放状态抖动。

### 4. 桌面歌词使用“每首歌曲一次”的稳定几何

桌面歌词不再在每一次活动行改变时按两行当前文本重新调整顶层窗口。改为在以下情况重新计算一次安全尺寸：

- 歌词文档改变；
- 字体或字号改变；
- 用户设置的基础宽度改变；
- 显示器可用区域发生有效变化。

计算时一次性测量当前歌曲可显示的歌词内容，得到该歌曲的稳定运行宽度；之后普通切句只替换文字并重绘，不再移动或缩放顶层窗口。拖动期间继续冻结几何，释放后只合并一次必要更新。位置保存以最终窗口位置为准，自动尺寸变化不会覆盖用户刚完成的拖动位置。

现有两行规则保持不变：第一行显示当前歌词，第二行优先显示翻译，否则显示下一句。自动宽度仍受当前屏幕可用区域保护。

#### 验收补充：切歌期间固定运行时视觉中心

切换歌曲时，歌词适配器会短暂发布空文档，再异步发布新歌词。桌面歌词窗口可能因此经历隐藏、按基础宽度收缩、按新歌词宽度扩展和重新显示。重新显示不得再次使用旧的持久化左上角坐标覆盖当前运行位置。

窗口首次显示或用户主动重置位置时，仍使用现有保存坐标和屏幕约束完成放置；首次放置后记录运行时视觉中心。切歌、空白加载和新歌词到达期间，即使窗口暂时隐藏，自动尺寸变化也必须围绕该运行时中心进行。重新显示时沿用该中心，不再次执行初始放置。用户拖动后更新运行时中心，继续作为后续切歌的锚点。

本修复不改变两行歌词、自动增宽、右键设置、锁定或鼠标穿透行为，也不改变现有位置设置的数据结构。

### 5. 沉浸歌词采用自绘纵向位移动画

动画只作用于 `LyricsCanvasV2` 的绘制偏移，不动画窗口、布局尺寸、字体大小、背景或透明度：

- 相邻歌词切换时，从上一行的实际绘制位置平滑移动到新锚点；
- 时长约 220 毫秒，使用缓出曲线；
- 当前行状态和逐字高亮立即切换到真实时间轴，只有画面位置做短暂追随；
- 动画中再次切句时，从当前可见偏移接续到最新目标，避免重新闪现；
- 手动拖动进度、点击歌词定位、切歌以及跨越多句时直接定位；
- 浏览歌词时不启动自动切句动画；
- “减少动画”开启时立即定位。

这样只增加一次轻量画布重绘，不创建逐行控件，也不触发布局重排，可避免为了动效再次引入卡顿。

## 涉及文件与代码区域

- `app/core/app_paths.py`：补充播放会话文件路径和初始化。
- `app/services/playback_session_store.py`：新增独立的会话读取、校验和原子写入帮助类。
- `app/services/production_playback_controller.py`：增加不播放的歌曲准备与延后定位能力。
- `app/ui_v2/adapters/playback_adapter.py`：向 UI 暴露恢复入口并同步暂停状态。
- `app/ui_v2/shell/main_window.py`：读取、延后恢复、合并保存和退出刷新。
- `app/ui_v2/shell/desktop_lyrics_window.py`：缓存每首歌曲的稳定宽度并消除切句几何更新。
- `app/ui_v2/widgets/lyrics_canvas_v2.py`：增加自绘纵向过渡状态。
- `app/ui_v2/pages/immersive_lyrics_page.py`：把“减少动画”设置传递给歌词画布。
- 对应测试文件与 `CHANGELOG.md` 的“未发布”章节。

## 测试设计

### 自动检查

- 会话文件缺失、损坏、旧字段和未知歌曲均可安全回退。
- 有效本地歌曲可恢复为已选择、指定进度且暂停，不触发播放。
- 队列和普通浏览路由可恢复；失效歌单路由回退到音乐库；沉浸路由回退到普通歌词页。
- 关闭“恢复上次会话”后不读取会话。
- 桌面歌词在连续长短句切换时窗口位置和尺寸保持稳定。
- 桌面歌词切换歌曲并经过空白加载阶段时，重新显示后视觉中心保持不变。
- 拖动期间切句不改变几何，释放后不发生二次位置跳动。
- 沉浸歌词相邻切句产生连续偏移并结束于零；跨句跳转、切歌和减少动画时立即定位。
- 现有播放、桌面歌词、沉浸歌词和路径回归测试继续通过。

### 手动验收

1. 播放一首本地歌曲到中间位置，停留在音乐库或歌词页，直接退出并重新启动。
2. 确认歌曲和进度恢复、界面不是“未选择歌曲”，但没有自动播放。
3. 点击播放，确认从恢复位置继续。
4. 让桌面歌词连续经过长句、短句并拖动窗口，确认不闪烁、不跳位。
5. 进入沉浸歌词，观察相邻切句为短促纵向滚动，逐字高亮仍与声音同步。
6. 拖动进度跨越多句以及开启“减少动画”，确认歌词直接定位而不播放长距离动画。

## 风险与控制

- 播放器准备媒体源和延后定位属于高风险区域，将通过独立入口隔离，不改现有正常播放入口。
- 某些在线来源在真正播放前无法验证可定位性；在线歌曲会恢复选择和进度记录，实际点击播放后再按来源能力定位，失败时维持现有错误提示。
- 整首歌词预计算宽度可能在切歌时增加一次字体测量，但避免了每句重复测量和顶层窗口移动，总体开销更低。
- 动画只改变绘制偏移并限制在相邻切句，避免窗口透明、布局变化或背景重新生成。

## 回滚

实现将保持为一个独立功能提交。若验收出现回归，可整体撤销该提交；`playback_session.json` 是可忽略的附加文件，不需要迁移或删除，旧版本也不会修改现有音乐库、歌单和设置数据。
