# HushPlayer Studio Listening Room 重构设计

## 结论与范围

上一轮 Quiet Orbit 优化解决了可用性与状态问题，但没有建立足以让用户一眼识别的产品级视觉系统。它保留了过多孤立的“标题 + 裸列表 + 小按钮”组合，信息层级、面板层次和主操作缺乏一致性。

本轮采用 **Studio Listening Room（静默听音室）** 方向：保留 HushPlayer 的深色、克制和低饱和暖金色识别，但将页面重新组织为稳定的内容画布、明确的操作层级和可扫描的播放工作区。

本轮不改动：

- `QMediaPlayer`、播放队列、上一首/下一首解析和真实播放控制；
- `library.json`、`playlists.json`、`stats.json`、设置与在线来源协议；
- 打包、应用内更新、旧 UI、用户数据或第三方依赖。

## 方案比较

### 方案 A：维持现有 Quiet Orbit，只增加细节

风险最低，但已经证明无法形成显著感知变化；不采用。

### 方案 B：Studio Listening Room（采用）

保留深墨绿灰与暖金色，只将暖金用于播放、确认、当前播放和少量关键强调。所有主要页面共享“画布 → 页面识别 → 操作带 → 内容面板”的结构。它可在不改变业务结构的前提下形成明显、成熟的产品感。

### 方案 C：高氛围电影式视觉

使用大面积封面、渐变、玻璃和动态背景。视觉变化最大，但会分散本地音乐库管理的效率，也增加渲染和兼容风险；不采用。

## 视觉系统

### 色彩与表面

- **Ink**：深墨底色，避免纯黑和 OLED 拖影；
- **Rail**：导航与窗口结构层；
- **Canvas**：页面主画布；
- **Panel / Raised Panel**：歌曲表格、搜索结果、来源行与弹窗的分层容器；
- **Fog / Bone**：数据文本与主文本；
- **Signal Gold**：唯一的主操作和播放语义；
- **Status**：成功、警告、不可用均使用文字/图标与颜色组合，不以颜色单独表达。

现有主题令牌继续是唯一颜色来源；不在页面里散落新的硬编码色值。

### 字体与密度

- 使用 Windows 的 Microsoft YaHei UI / Segoe UI Variable 回退链；
- 采用 `12 / 13 / 15 / 18 / 26 / 34` 的稳定文字层级；
- 采用 `4 / 8 / 12 / 16 / 24 / 32` 的间距节奏；
- 表格仍以内容为主，但放入有边界、留白和清楚表头的工作面板；
- 一屏只保留一个强主操作，其他操作降级为次级或溢出动作。

### 标志性结构

每个内容页以“识别条 + 工作面板”替代裸标题：

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 音乐库  ·  全部歌曲                                      [页内搜索] │
│ 30 首歌曲 · 1:09:23       [▶ 播放全部] [↯ 随机播放]                │
├──────────────────────────────────────────────────────────────────────┤
│  #    歌曲                    歌手       专辑       时长      ⋯    │
│  1    封面  标题 / 次级信息   ...                                  │
│  ...                                                                 │
└──────────────────────────────────────────────────────────────────────┘
```

歌单和“我喜欢”保留封面英雄区，但让封面、标题、元信息和动作成为同一张有边界的内容面板，而不是漂浮在大面积空白上。

## 页面与组件改造

### 1. 主外壳

- 标题栏改为更轻的结构条；搜索框、返回/前进、设置和窗口控制按明确的左右区域排列。
- 侧栏作为 Rail：一级媒体入口与个人歌单在视觉上分组，当前页使用细窄强调条 + 背景 + 字重，而不是单纯底色。
- 内容区使用 Canvas，固定播放器使用 Raised Panel 语义并保持不遮挡滚动内容。

### 2. 集合与歌曲列表

- `PageHeader` 提供可扫描的标题、数量/时长和页内搜索；
- `SectionToolbar` 形成明确主/次操作层级；
- `TrackListPage` 用共享工作面板包裹工具栏与表格，空状态也在相同空间中呈现；
- 表格表头、行悬停、选中、播放中、失效和右键菜单使用统一的层级语言。

### 3. 浏览、在线搜索与来源

- 浏览页减少无目的空白，段落变成平衡的内容行；
- 在线搜索将搜索输入、来源范围和结果控制整合成一条 Search Station，不再像几行松散文字；
- 来源管理使用一致的来源卡片与状态标签，停用明确表示“保留，可重新启用”。

### 4. 失效歌曲恢复与弹窗

- 恢复窗口成为固定标题、可滚动候选区、固定确认栏的工作流弹窗；
- 当前选择有独立摘要，确认按钮用清晰文案“替换播放来源并播放”；
- 不改变原歌单成员、收藏关系、排序位置或歌曲身份。

### 5. 播放底栏

- 保持现有播放逻辑和响应式规则；
- 视觉上加强“现在播放”信息组、传输控制组、实用控制组的边界，避免像三块无关联控件；
- 仅使用短、稳定的标签和固定尺寸，长信息用省略与工具提示保留。

## 实施批次

1. **视觉基础与集合页**：主题表面、标题栏、侧栏、通用页头、操作条、歌曲工作面板。
2. **搜索与恢复工作流**：在线搜索、来源管理、失效歌曲恢复弹窗的结构和状态。
3. **浏览与播放收口**：浏览页内容密度、播放器视觉收口、主题/窄窗口/键盘焦点验证。

每批都做独立本地提交。每批前后检查高频交互、窄窗口、深浅主题、加载/空/失败状态；不会重打包或推送。

## 验收标准

- 在音乐库、我喜欢、歌单、在线搜索和来源管理间切换时，用户能立即辨识当前区域、当前内容和主操作；
- 1024px 与 1440px 下无横向溢出、遮挡或播放器控件重叠；
- 搜索、收藏、右键菜单、失效歌曲恢复和在线来源启停保留原有业务行为；
- 深色与浅色主题均保持可读，键盘焦点和图标按钮有可辨识状态；
- 用户数据和正式安装/更新流程不发生改写。
