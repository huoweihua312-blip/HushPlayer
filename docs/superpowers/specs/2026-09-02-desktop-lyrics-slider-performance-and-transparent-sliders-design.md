# 桌面歌词滑块性能与全局透明滑块设计

- 状态：已获用户确认，准备实施
- 日期：2026-09-02
- 范围：UI V2 桌面歌词预览、全局滑块样式、沉浸歌词滑块

## 背景

桌面歌词字号和宽度滑块会在每个值变化时直接调用完整的窗口设置流程。该流程包含窗口重排、字体更新、歌词高度测量和状态同步，连续拖动时容易产生卡顿和缩放跳动。部分普通 `QSlider` 只定义了轨道和滑块伪元素，没有明确设置控件本体透明背景，在 Windows 原生样式下会出现矩形底板。

## 目标

1. 桌面歌词字号、宽度滑块保持实时预览，但将连续变化合并为约 40ms 一次的最新值刷新。
2. 桌面歌词预览只更新必要的字体、宽度和内容高度，不重复刷新整套主题样式。
3. 窗口实际尺寸变化后，歌词表面和标签使用最新几何尺寸，长歌词不会因旧的子区域高度被裁切。
4. 全部生产 UI 滑块和现有预览滑块都使用透明控件背景，仅保留细轨道、进度填充和圆形滑块。

## 非目标与约束

- 不修改 `QMediaPlayer`、播放队列、播放上下文或歌词时间轴数据。
- 不改变设置 JSON 字段和取值范围。
- 不新增第三方依赖。
- 不取消桌面歌词的实时预览、鼠标穿透、右键设置和托盘解锁。

## 方案

### 预览事件合并

`MainWindow` 增加单次触发的预览定时器。字号和宽度变化只更新待处理快照并启动定时器；定时器到期时仅把最后一个快照应用到 `DesktopLyricsWindow`。颜色、字体、穿透等低频变化仍立即应用。保存定时器继续负责 250ms 后的持久化，预览与保存职责分离。

### 桌面歌词轻量应用路径

`DesktopLyricsWindow.apply_settings` 增加仅用于实时预览的可选路径。该路径保留当前运行时高度，更新窗口宽度和歌词字体后重新测量实际换行高度，并显式同步透明歌词表面几何区域。完整设置应用仍用于初始化、恢复设置和非连续设置变更。

### 滑块样式

在应用级样式和各个局部滑块样式中明确声明：`QSlider` 本体 `background: transparent; border: 0; padding: 0`。轨道、已选区域、未选区域、滑块和禁用状态继续使用主题色，不去除可见的操作反馈和键盘焦点环。

## 数据流

```text
字号/宽度拖动
  -> 快照校验
  -> 合并预览定时器（约 40ms）
  -> DesktopLyricsWindow 轻量应用
  -> 字体/宽度/换行高度更新
  -> 250ms 保存定时器
  -> 设置桥接持久化
```

## 验证

- 运行桌面歌词、关闭行为、主窗口和沉浸歌词相关回归测试。
- 检查所有修改的 Python 文件可编译、文本保持 UTF-8。
- 检查生产和预览滑块的本体样式包含透明背景声明。
- Windows 手动确认：拖动字号/宽度无明显卡顿；长歌词完整显示；普通歌词、播放器和沉浸歌词滑块均无矩形底板。

## 风险与回滚

实时预览仍会改变桌面歌词窗口的字号和宽度，Windows 不同 DPI 或字体渲染器可能产生轻微高度差。若实际桌面效果不符合预期，可回滚本轮实现提交；持久化设置结构不变，不需要数据迁移。
