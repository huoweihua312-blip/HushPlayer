# Quiet Orbit 用户视角界面优化设计

## 背景

在线版本选择弹窗出现浅色/深色主题不一致、按钮文字不可见、候选内容裁切等问题。只修复该弹窗会让相同问题继续出现在其它交互面，因此本轮按用户实际使用路径统一检查弹窗、在线搜索、来源管理、失效歌曲恢复、播放器底栏和启动体验。

## 目标

1. 所有 Quiet Orbit 自定义弹窗在浅色和深色主题下都具备可读的文字、按钮、列表、焦点和禁用状态。
2. 在线版本候选不会因固定尺寸、长标题或底部按钮区而被裁切。
3. 在线搜索把结果区域作为主要内容，来源和状态信息保持可见但不挤占结果。
4. 失效歌曲的恢复入口说明清楚，恢复动作只更换播放来源，不删除歌单位置、收藏关系或其它歌曲信息。
5. 窄窗口下播放器底栏不遮挡收藏和播放控制。
6. 启动和切换路径只做可测量、低风险的延迟加载与重复刷新削减，不重写播放队列、媒体播放器或持久化结构。

## 实施顺序

### 第一批：弹窗和候选选择器

- 在 `app/ui_v2/theme/styles.py` 增加独立的弹窗样式构建函数，集中定义 QDialog、QLabel、QListWidget、QPushButton、QToolButton、输入控件、滚动条及焦点/禁用状态。
- 让在线恢复候选弹窗使用独立样式，而不是把普通页面样式直接当作弹窗完整样式。
- 将候选行改为稳定的两行信息布局，保留标题、歌手、专辑、来源和时长；长文本省略并提供完整提示。
- 弹窗根据屏幕和候选数量设置合理的默认尺寸，底部动作区固定保留空间。
- 增加浅色/深色主题、按钮可见性、选中候选、键盘确认和长文本布局回归测试。

### 第二批：搜索、来源和失效歌曲体验

- 压缩在线搜索页的非结果区域，搜索结果、排序和来源筛选保持主要视觉权重。
- 统一来源管理页面的操作文案、禁用/失败/重试状态和窄宽度行为。
- 失效歌曲显示明确的“在线寻找并播放”或“替换播放来源”操作；恢复成功后只更新播放来源并保留原关系。
- 不修改来源协议、下载行为、歌单 JSON 结构或在线音频版权边界。

### 第三批：底栏和性能

- 检查播放器底栏在常见窗口宽度下的最小尺寸、标题省略和收藏按钮可用区域。
- 通过现有测试和轻量测量寻找启动阶段重复初始化、重复刷新和同步阻塞点。
- 只做局部延迟初始化、去重刷新或后台已有服务的调度优化；不直接替换 QMediaPlayer、播放队列或 worker 架构。

## 视觉和交互原则

- 继续使用现有 Quiet Orbit 语义色、字体和圆角令牌，不引入第二套视觉系统。
- 主操作使用明确动词，例如“替换播放来源并播放”；取消、禁用和失败状态必须有足够对比度。
- 所有重要操作保留键盘焦点、AccessibleName 和稳定的点击区域。
- 长标题、专辑名、来源名统一省略显示，悬停或辅助文本提供完整信息。
- 异步状态必须说明当前阶段和下一步动作；空状态不是空白区域。

## 非目标和保护范围

- 不迁移数据库、不改变 `library.json`、`playlists.json`、`stats.json` 结构。
- 不删除旧 UI、来源协议、兼容逻辑或正式发布产物。
- 不添加第三方依赖。
- 不进行大规模拆分或重写 `main_window.py`。

## 回归验证

- 修改 Python 文件后逐文件 `py_compile`。
- 运行现有 V2 主题、在线搜索、在线恢复、真实交互和播放相关测试。
- 新增弹窗视觉契约测试，至少覆盖两种主题、候选列表、操作按钮、键盘确认、窗口缩放和长文本。
- 使用 offscreen 轻量启动验证页面切换、设置来源页和失效歌曲恢复入口。
- 最终检查 `git diff --check`、tracked 文件状态和 `CLEANUP_AUDIT.md` 未被纳入提交。

## 回滚

本轮改动按功能文件分组提交；若视觉改动引发回归，可回滚对应提交，不触碰发布 tag、远端 Release、用户数据和既有清理审计文件。
