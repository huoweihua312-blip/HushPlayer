# HushPlayer 桌面歌词输入恢复与罗马音移除设计

## 1. 背景与目标

桌面歌词“直接右键 + 单按钮锁定”在离屏自动测试中通过，但 Windows 实机验收暴露出四个问题：

1. 锁按钮出现不需要的黄色焦点边框。
2. 解锁后右键歌词不稳定，可能无法打开快捷设置。
3. 设置浮层打开后可能丢失鼠标释放事件，歌词持续跟随指针且无法取消。
4. 没有翻译或罗马音时只显示当前一句，未满足双行歌词预期。

同时，用户确认取消整个软件的罗马音界面和显示能力。本轮把桌面歌词输入恢复、双行规则和罗马音移除作为同一个歌词体验修复任务处理。

## 2. 已确认产品规则

- 采用独立锁按钮窗口，不再让歌词窗口因悬停而切换输入穿透标志。
- 锁按钮无黄色边框、无文字、无键盘焦点，只保留锁定 / 解锁图标和中性悬停底色。
- 锁定时歌词窗口始终鼠标穿透；独立锁按钮仍可点击。
- 解锁时左键拖动、右键打开快捷设置。
- 默认两行是“当前句 + 下一句”。
- 开启翻译后，两行是“当前句 + 当前句翻译”，不再显示下一句。
- 最后一行、无下一句或空歌词时允许只有一行或隐藏。
- 普通歌词、沉浸歌词、桌面歌词、设置页和可运行的实验预览都不再提供或显示罗马音。
- 底层罗马音字段仅保留兼容读取，避免旧设置、旧缓存和旧歌词数据报错。

## 3. 方案选择

### 3.1 采用：独立锁按钮窗口

新增一个由 `DesktopLyricsWindow` 持有的轻量顶层锁控件。它使用无边框、置顶、透明背景和不抢焦点的窗口标志，生命周期仍由桌面歌词窗口统一管理。

采用该方案的原因：

- `WindowTransparentForInput` 作用于整个顶层窗口，子按钮无法成为例外。
- 当前实现在悬停时反复重建歌词窗口的原生输入状态，容易和鼠标捕获、弹出窗口及释放事件竞态。
- 独立控件允许歌词窗口在锁定期间始终穿透，只有 `32 × 32 px` 的按钮区域接收点击。
- 悬停只控制锁按钮的显示与隐藏，不再改变歌词窗口原生句柄状态。

### 3.2 不采用的方案

- **继续使用歌词窗口子按钮**：改动较小，但仍需在悬停时切换整个歌词窗口输入状态，无法消除已出现的实机竞态。
- **锁定后只从播放器底栏解锁**：最稳定，但违反已确认的“悬停歌词可解锁”交互。
- **安装全局鼠标钩子**：侵入性强、维护风险高，也不符合轻量和非打扰原则。

## 4. 桌面歌词窗口职责

### 4.1 锁定偏好与原生输入

- 继续使用 `floating_lyrics_passthrough` 表示用户锁定偏好。
- 只有初始化、用户点击锁定 / 解锁或设置浮层修改穿透开关时，才允许改变歌词窗口的 `WindowTransparentForInput`。
- 光标进入或离开歌词范围时不得改变歌词窗口输入标志。
- 锁定偏好保存失败时，沿用现有设置快照回退，歌词窗口和锁按钮都恢复到最近一次成功保存的状态。

### 4.2 独立锁按钮

- 控件视觉尺寸约 `32 × 32 px`，定位在歌词窗口上边缘中央。
- 使用现有轮廓锁图标；解锁态显示“锁定”图标，锁定态显示“解锁”图标。
- `NoFocus`，所有状态均无边框；悬停或按下时只使用主题中的中性背景。
- 控件平时隐藏。桌面歌词可见且指针进入歌词范围时显示，离开后短延时隐藏。
- 锁定时歌词主体不会收到进入 / 离开事件，因此由桌面歌词控制器启动低频 `QTimer`，读取 `QCursor.pos()` 并判断指针是否位于歌词全局矩形或已显示的锁按钮矩形内。定时器只在桌面歌词可见时运行，不安装全局鼠标钩子。
- 解锁态也复用同一范围判断，避免在歌词窗口和独立按钮之间移动时反复闪烁；连续离开歌词与按钮范围后才执行延时隐藏。
- 点击锁定后立即隐藏，直到指针离开歌词范围并再次进入，避免同一位置立即显示“解锁”造成视觉跳变。
- 桌面歌词隐藏、无可显示歌词、窗口关闭或应用退出时，锁按钮必须同步隐藏和释放。
- 多显示器、DPI 或歌词宽度变化时，锁按钮根据歌词窗口全局位置重新定位并夹紧在对应屏幕。

## 5. 指针与拖动状态机

### 5.1 右键设置

- 解锁态在右键释放后打开设置，避免鼠标按键仍按下时创建 `Qt.Popup`。
- 歌词表面和顶层窗口都通过同一个右键状态处理入口，不能只依赖 `QContextMenuEvent`。
- 右键按下时不启动拖动；释放时只发出一次设置请求。
- 打开设置前先结束任何未完成拖动并释放鼠标捕获。
- 锁定态右键继续穿透到下层窗口，不打开设置。
- 播放器底栏右键入口继续保留。

### 5.2 左键拖动

- 只有解锁、设置浮层关闭且左键按下时才能开始拖动。
- 开始拖动后调用 Qt 鼠标捕获，确保指针离开歌词区域后仍能收到释放事件。
- 移动事件若检测不到左键仍按下，立即结束拖动并保存最终位置。
- 左键释放时结束拖动、释放捕获并持久化位置。
- 以下情况必须无条件取消拖动并释放捕获：
  - 按 `Esc`。
  - 桌面歌词隐藏或关闭。
  - 窗口失去激活状态。
  - 用户锁定歌词。
  - 快捷设置即将打开。
  - 应用开始退出。
- 取消后不得继续响应旧移动事件，也不得改变播放、歌词活动行或页面路由。

### 5.3 设置浮层生命周期

- `DesktopLyricsQuickSettingsPopover` 发出显示状态变化。
- 浮层显示前通知桌面歌词取消拖动并暂停新的拖动 / 右键请求。
- 浮层关闭后恢复正常交互；若当前是锁定态，歌词窗口保持穿透。
- 浮层自身继续使用即时预览、250 ms 防抖保存和失败回退，不新增“保存 / 取消”按钮。

## 6. 双行歌词规则

为 `LyricsAdapter` 增加只读的下一句访问能力，不改变歌词解析、时间戳定位或活动行算法。

桌面歌词渲染顺序：

1. 当前活动行文本作为第一行。
2. 若翻译显示已开启且当前行有翻译，第二行使用当前行翻译。
3. 否则，若文档中存在下一句且文本非空，第二行使用下一句原文。
4. 否则隐藏第二行。

第二行继续使用较小字号、较低透明度和现有轻微水平错位。只有文本实际变化时才更新标签，保留防闪烁行为。

## 7. 全软件取消罗马音

### 7.1 用户可见内容

从以下位置移除罗马音按钮、开关、字号滑块、提示和渲染：

- 普通歌词紧凑工具栏和旧歌词标题控件。
- 沉浸歌词顶部控制、快捷设置、设置面板和画布。
- 主设置页及设置搜索结果。
- 桌面歌词第二行。
- 当前仍可运行的沉浸歌词实验预览。
- 未发布更新日志中的罗马音功能描述。

涉及整体字号的帮助文本改为只描述当前歌词、普通歌词和翻译，不再提及罗马音。

### 7.2 运行时行为

- `LyricsAdapter.display_options["romanization"]` 为兼容旧消费者可继续存在，但固定返回 `False`。
- 兼容用 `toggle_romanization()` 如保留，只能确保状态为关闭，不得再切换为开启。
- 普通和沉浸歌词画布忽略任何旧设置或旧调用中的罗马音可见值。
- 设置加载时即使旧文件中保存为开启，也不得在界面或画布中恢复。

### 7.3 兼容字段

暂不删除以下字段或数据成员：

- `LyricLine.romanization`
- `LyricsDocument.has_romanization`
- `SettingsState.show_romanization`
- `ImmersiveLyricsOptions.romanization_font_size`
- 对应旧设置字段和 mock 数据字段

这些字段只用于兼容反序列化、旧缓存、插件或测试数据，不再对应用户可见功能。未知设置字段继续保留，不执行数据迁移。

历史正式更新日志和已提交的旧设计文档保持原样，避免改写历史事实；只修改 `CHANGELOG.md` 的“未发布”章节。

## 10. 检查与验收

### 10.1 自动检查

- 桌面歌词锁定时始终保留 `WindowTransparentForInput`，悬停锁按钮不会改变该标志。
- 锁按钮为独立顶层控件，无焦点、无边框且位置跟随歌词窗口。
- 锁定时通过可见期低频指针检测发现进入歌词区域，不依赖穿透窗口的悬停事件，也不使用全局钩子。
- 右键按下不打开设置，右键释放只打开一次。
- 设置打开、窗口失焦、按 `Esc`、左键丢失、隐藏和关闭均会清理拖动状态与鼠标捕获。
- 默认第二行显示下一句；翻译开启时第二行优先显示当前句翻译。
- 普通、沉浸、桌面和实验预览均没有可见罗马音入口或渲染。
- 旧罗马音兼容字段仍可读取，运行时显示状态固定为关闭。
- 运行桌面歌词、普通歌词、沉浸歌词、设置、真实交互和内容契约回归。
- 对所有修改 Python 文件执行 `py_compile`，并执行 UTF-8、乱码和 Git 差异检查。

### 10.2 Windows 手动验收

1. 显示桌面歌词，确认锁按钮没有黄色边框。
2. 锁定并把鼠标移到歌词上，确认歌词主体仍可穿透，只有锁按钮可点击。
3. 解锁后右键歌词，确认设置只打开一次且鼠标未被锁住。
4. 打开和关闭设置后移动鼠标，确认歌词不会跟随。
5. 拖动歌词后在窗口内、窗口外和快速移动情况下释放，确认均能停止。
6. 拖动中按 `Esc`、锁定歌词或打开设置，确认立即取消拖动。
7. 播放无翻译歌曲，确认显示当前句和下一句。
8. 开启翻译，确认第二行变为当前句翻译。
9. 检查普通歌词、沉浸歌词和设置页，确认没有罗马音按钮、开关或字号设置。
10. 重启应用，确认锁定、位置和其他歌词设置仍正常保存。

## 11. 风险与回滚

高风险点是 Windows 顶层窗口输入标志、鼠标捕获和弹出窗口生命周期。独立锁按钮把输入切换频率降到只有显式锁定变化时，风险低于继续修补当前悬停切换方案。

设计与实现分别使用聚焦提交。若发生实机回归，可整体回滚实现提交；没有新增字段或数据迁移，回滚不需要转换用户数据。罗马音兼容字段继续保留，因此回滚或跨版本读取不会因字段缺失失败。
