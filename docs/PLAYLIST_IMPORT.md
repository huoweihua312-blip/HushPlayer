# 跨平台歌单导入

面向普通用户的歌单迁移：把其他平台（或导出文件）里的歌单搬进 HushPlayer，并尽量匹配到本地曲库或已启用的在线音源。

## 支持范围（真实验证状态）

| 平台 | 链接导入 | 文件导入 | 说明 |
| --- | --- | --- | --- |
| 网易云音乐 | ✅ 公开歌单 | ✅ | `music.163.com/api/v6/playlist/detail` 读取；私密/需要登录的歌单不可用 |
| Apple Music | ⚠️ 不提供在线解析 | ✅ 优先 | 需要开发者令牌；请用「文件 → 资料库 → 导出」得到 `Library.xml`，或导出 m3u8/csv |
| QQ 音乐 | ⚠️ 不支持 | ✅ | 需要登录 Cookie；请导出歌单文件 |
| 酷狗音乐 | ⚠️ 不支持 | ✅ | 同上 |
| 酷我音乐 | ⚠️ 不支持 | ✅ | 同上 |

「⚠️ 不支持」是**产品选择**，不是待办：不绕过登录、付费墙或 DRM。粘贴这些平台的链接时，向导会识别平台并提示改用文件导入，不会假装成功。

## 文件格式

- `m3u` / `m3u8`：支持 `#PLAYLIST:`、`#EXTINF`（时长、「歌手 - 歌名」）、`#EXTART`、`#EXTALB`，以及本地路径行。
- `pls`：`FileN` / `TitleN` / `LengthN`。
- `csv`：自动识别中英文表头（title/name/歌曲/歌名/曲名、artist/歌手/艺人、album/专辑、duration/时长、path/路径），无表头时按 3/2/1 列退化。
- `txt`：一行一首，支持「歌手 - 歌名」、`1.` / `01、` 序号、`[03:12]` / `(03:12)` 时间戳。
- `xml` / `plist`：Apple Music / iTunes `Library.xml`，按 `Playlists[].Playlist Items` 还原顺序；没有同名歌单时取第一个非主歌单。

编码：BOM（UTF-16）优先，其次 `utf-8-sig` → `gb18030` → `big5` → `latin-1`。

## 匹配流程

1. **本地曲库**：按标题 + 歌手 + 时长打分，命中即「本地」。
2. **在线音源**：只用已启用且声明了搜索能力的音源，最多 3 个源并行，单行超时 8s；候选再经 `resolve_playback` 验证，验证失败的标为「在线未验证」（找到歌但当前放不了），不会算作可播放。
3. **决策**：分数 ≥ 80 且领先第二名 ≥ 15 → 自动匹配；55–79 → 「待确认」，保留前 5 个候选；< 55 → 「未匹配」。
4. 版本差异（Live / Remix / 伴奏 / 翻唱 / 纯音乐…）参与加减分，避免把 Live 版当成原版。

评分复用 `hushplayer/online/matching.py`，与播放时的跨源回退共用同一套逻辑，不维护两套。

## 向导

选择来源 → 获取歌曲 → 智能匹配 → 完成导入。

- 来源页：选文件、粘贴链接（网易云识别后可直接抓取）、或粘贴文本。
- 匹配页：逐行显示「状态 / 原始歌曲 / 匹配结果 / 评分 / 来源」，双击一行可换候选、手动搜索、跳过、取消跳过、重新匹配。
- 同名歌单：合并 / 覆盖 / 另建，都会先询问，不会静默覆盖。
- 完成页：导入统计与「打开歌单」。

并发与响应：本地阶段每 25 行让出一次事件循环；在线阶段最多 2 行在飞；同一首歌（归一化标题 + 歌手）只查一次；`cancel()` 会停止后续请求。

## 代码位置

- `hushplayer/services/playlist_import.py`：解析（m3u/pls/csv/txt/xml）+ `match_tracks` + `import_playlist_file`（旧 API 保留）。
- `hushplayer/services/playlist_link.py`：平台识别、ID 提取、网易云抓取。
- `hushplayer/services/playlist_matcher.py`：本地/在线两阶段匹配、候选、`apply_import`（new/merge/replace）。
- `hushplayer/ui/playlist_import_dialog.py`：向导 UI。
- 测试：`tests/test_playlist_import.py`（解析与匹配 21 项）、`tests/test_playlist_dialog.py`（向导 2 项）。

## 已知限制

- 网易云以外的链接导入未实现（见上表原因）。
- 在线匹配质量取决于音源返回的元数据；同名不同歌手的翻唱可能进入「待确认」而不是自动匹配。
- 大歌单（>500 首）的匹配耗时与网络有关，当前是串行限并发，未做断点续传；关闭向导会取消剩余请求。
- Apple Music 的地区曲库差异无法在匹配阶段识别，未匹配会如实计数。
